# 第三轮自审（2026-09-30，对提交版 `3a0c709` 的审稿）

审稿对象：`paper/build_eurosp/main_eurosp.pdf`（正文 13 页）、`hesp_research/`（代码、协议、结果）。
审稿立场：EuroS&P / RAID 级别安全会议的严格审稿人；只根据稿件和仓库中的证据下结论。

## 总评

**建议：核心思路需要改，数据不需要推翻。**

实验纪律（预注册、冻结、审计、勘误）是这篇稿子最强的部分，7 项研究的数字本身可靠。问题在于稿件的主张和证据之间的关系：稿件把"控制器在结构化观测下不需要 LLM"当作主结果，而这个结果在稿件自己的环境里是**按构造成立**的；稿件里真正新的、有安全含量的发现（模型一旦必须读原始日志，攻击者的通道就从"一个来源"扩大到"模型读到的每一个来源"）被放在结果部分的第三小节，规模最小，而且没有测自适应攻击。按现在的主线投出去，我预计仍是 weak reject；理由如下。

## 主要问题

### P1（核心）主结果按构造成立

- 三个任务族都是封闭世界：候选原因互斥且给定、观测是有限词表上的离散标签、环境主动报告状态变化、预测表从**同一生成器**计数得到。前两个任务族几乎是确定性的。
- 在这种环境里，贝叶斯账本 + 期望信息增益是教科书最优解（稿件自己引用 de Kleer 1987、Golovin 2010）。它完成全部案例不是发现，是设置的推论。"没有任何模型能在此之上增加什么"（PE1 无增益）同样是推论：一个已经最优的程序上面加任何东西都不会有增益。
- 审稿人的读法会是：作者构造了一个经典方法最优、LLM 最不利的环境，然后报告经典方法赢了。这在安全会议上不构成贡献。

### P2 主线漂移，且现在的主线是一个否定结果

- v0.5 的问题是"控制器有帮助吗"，v1.1 变成"LLM 没有增益"，v1.2 变成"控制权分配"。三轮改版都在换主线，审稿人能看出稿件在找题目。
- 现在的题目和摘要实际上在说"LLM 在这里没有用"。这是一个否定结果，而且是在对 LLM 最不利的设置里得到的；它既不是系统贡献也不是攻击/防御贡献。

### P3 安全结果大部分是架构推论，实验只确认代码按设计工作

- "结束守卫在所有模型上阻断注入"：注入文本按设计进不了账本（分类器只读结构化字段），守卫又只接受账本里的证据，所以守卫必然阻断。五个模型 0/72 只说明代码正确。
- "伪造来源击败控制器"：控制器按设计信任探针，最信息量的观测先被采用，所以单个伪造来源必然决定结论。
- "来源组佐证挡住伪造来源"：规则按设计计数来源组，所以按来源组注入的伪造必然被挡。
- 这些都值得写，但它们是设计的推论，不能撑起"安全边界"这个贡献。

### P4 真正的安全发现在 §6.3，但攻击不是自适应的，防御结论可能不成立

- §6.3 是稿件里唯一一个"模型确实有用"的地方，也是攻击面重新打开的地方。这才是一篇安全论文该有的主线：**模型读，控制器决；攻击者的通道随控制权的分配而移动**。
- 但现在的注入攻击只在 4 个探针（`source_ips`、`threat_intel`、`change_ticket`、`access_pattern`）写入声称，Qwen-7B 只采纳了 46%（48/105），Llama-8B 采纳 1/71。"账本交叉检验挡住了"是因为采纳是部分的、其余探针给出真实读数。
- 一个自适应攻击者会在**所有**探针的自由文本字段里注入一致的"授权扫描"故事。按 `secapp.py` 的真实分布可以直接推算：对 credential_stuffing，若解析器采纳 `source_ips`、`threat_intel`、`change_ticket`、`access_pattern` 四条声称，authorized_scan 的后验乘积约为 0.992×0.85×0.992×0.992×0.005（`auth_log` 反证）≈ 4×10⁻³，credential_stuffing 约为 0.002×0.003×0.002×1.0 ≈ 10⁻⁸，authorized_scan 稳定超过 0.8，而它得到 ip_reputation、itsm、http_logs **三个来源组**的特异性支持——**稿件推荐的按来源组佐证会被击穿**，因为注入随每个探针的响应到达，来源组的独立性在解析层不成立。
- 也就是说，稿件的部署建议（"来源组佐证 + 守卫 + 确认停止"）在稿件自己指出的最现实设置（模型读原始日志）下没有被测试，而按表推算是失效的。这是核心漏洞，必须补实验，而不是改措辞。

### P5 评价标准与真实性

- 验证器要求"只有该原因才会产生的一条观测"，comp-triage 和联合验证器是对审稿的回应，但仍是我们写的三个场景。
- 公开数据部分（§6.7）的结论是"没有一个合适"，这对论文没有正面贡献，只占篇幅。

## 次要问题

- 表 1（研究概览）把 v0.5–v1.2 九行都列出来，读者看到的是"改了九次"；应按问题合并。
- §6.1 与 §6.2 之间的"posterior stop 由排除得出结论"细节过多，占了主线篇幅。
- 摘要最后一句才出现真正的新发现；题目问的是"哪些决定该留给 LLM"，答案"几乎没有"让读者失去继续读的理由。
- "21,278 个审计回合"里大部分来自现在被称为消融的配置；数字大不等于证据强，审稿人会反感。

## 处置方案（已获授权改主线时的做法）

**新主线：不可信读取器、可信决策器。**
LLM 作为不可信解析器（把原始日志读成账本能用的标签），控制器作为可验证的决策器（选探针、判证据、停止）。论文的中心问题从"LLM 该保留哪些决定"改为"**把决策交给控制器后，攻击者还剩哪些通道，各需要什么规则**"。三条通道对应三种控制权分配：

1. 模型决定 → 指令注入（守卫关闭）；
2. 控制器决定、探针可信 → 伪造来源（来源组佐证关闭）；
3. 控制器决定、模型读取 → **解析器采纳**（新通道：来源组佐证无效，需要"读取器信任"规则——LLM 解析出的观测可以更新后验、可以确认需处置的原因，但不能作为良性结论的特异性证据）。

原有结果的位置：

- "无增益"（PE1）和"公平提示"（v1.2-C）变成支撑：把决策交给控制器**不损失**完成率，所以把模型限制为读取器是可以承受的。
- 证据政策前沿（v1.2-B）变成决策器的设计空间。
- 表误差、第二任务族、公开数据审计进入附录或压缩。

**需要补的实验（v1.3，H100，Qwen-7B / Llama-8B）：**

- 攻击：A1 现有四探针注入；A2 全探针一致注入（完整的 authorized_scan 故事）；A3 漂移格式 + 全探针注入（规则解析器无法兜底）；A4 日志行注入（自由文本里带换行伪造一整行 `probe=... ` 记录）。
- 防御：D0 只用 LLM 解析器；D1 规则优先、LLM 兜底；D2 读取器信任（如上）；D3 剥离已知自由文本字段。
- 控制器固定为推荐配置（EIG/cost、确认停止、按来源组佐证、恢复规则）。
- 不含 LLM 的上界：以"全部采纳"的脚本解析器代替模型，给出每种攻击在采纳率 1.0 下的结果（说明攻击在原理上是否成立）。
- 预注册主要终点：A2 与 A3 下 D2 相对 D0 的 missed-attack 差（按任务聚类 bootstrap）。良性代价：两个良性原因下 D2 的升级数。
