# 研究协议草案 v0.1（真实实验前冻结）

## 核心假设和反证条件

H1：控制模型、工具、可见任务信息与总预算后，HESP 在结构化记忆对照之外，提高任务完成率或减少有效完成任务所需的资源。

反证/负结果包括：没有稳定改善；改善只来自更长提示或更多模型调用；仅在人工规则覆盖的题型有效；任务完成率下降且没有合理的成本收益；只能在公开题解泄漏的任务上奏效。

本协议属于计划，不是已经完成的实验。该框架目前不主张首创“假设推理”或“信息增益”。

## A / B / C 的公平比较

- A：统一基础模型的 ReAct 风格工具循环。应复核原始实现并写清差异。
- B：A + 结构化假设、证据、业务状态。模型仍决定行动。
- C：B + 执行前预测、按诊断价值选择行动。
- 当前程序是三个接口的脚本模拟。真实实验前必须接入同一模型，并让真实候选/预测由固定的生成机制产生。
- 各组共享工具权限、环境重置、输出解析、硬预算、基础精确去重。不能只给 C 去重保护再把全部重复率收益算成诊断规划贡献。
- 当前 A 隐藏内部结构化记录，B/C 可见；内部仍计算记录用于统一日志，这不代表 A 的模型使用了这些记录。
- 另设“B + 同等计算量反思”对照，排除更多推理开销造成的收益。
- 分别报告相同工具预算、相同端到端成本预算的结果。候选生成、预测、解析、失败重试和最终判断的模型调用均应计入。

## 数据与难度

先用少量授权的本地任务调试，不以这些任务作最终测试集。正式任务规模由模型价格、时间和 pilot 方差决定，不预先编造 N。

按应用家族/题目来源划分开发与测试集，不能把同一题的轻微改写同时放在两边。保留需要身份切换、对象关系或多轮前置状态的任务子集，单独分析。记录题解公开程度及可能的模型训练污染。不能以完成 CTF 推断大型真实网站能力。

任务 manifest 应记录：任务 ID、授权范围、来源/许可、镜像摘要、初始状态、重置操作、独立成功判定、分组标签、环境超时与异常规则。隐藏答案和题解不能出现在 Planner 输入。

## 预期信息增益的使用边界

当前实现严格计算“给定预测表模型下的 EIG”。它不保证现实中的真实信息增益。第一版的预测表是人为指定的模拟规则，环境观察又是确定性的，所以这不是校准实验。

真实版应先固定结果分类，再让预测器在执行前给出各假设下的结果分布，保存原文及解析值。在开发集评估结果预测的对数损失/Brier 分数与校准情况，不能把模型自报百分比直接当成事实。

多个漏洞可以共存。只在同一个局部症状的竞争解释内使用互斥分布。保留“其他/当前无法解释”，遇到预测范围外的结果触发假设扩展，而非强行归一化到已有漏洞。

一次未报错不等于反证。只有测试确实执行、前提成立、预期信号具备可检测性时，未出现预测信号才可能降低假设支持程度。重试同一请求也不是多条独立证据。

## 指标与统计口径

主要指标：独立验证器确认的完成率。失败、超时、预算耗尽、模型格式错误、环境错误分别报告，不能悄悄删除失败任务。

次要指标：总模型输入/输出 Token、总工具调用、端到端时间、实际费用、成功任务的资源消耗。缺失 usage 记 unknown，不记 0。

重复操作要分为“提出后被拦截”和“实际执行重复”，并说明指纹规则。语义重复率需独立人工标注或单独验证的评估器，不能用 C 自己的判断作为唯一裁判。

业务状态错误率和证据解释质量需要标注规则、抽样与盲评。预测熵减少只是模型内部指标，不能作为实际任务进展的替代。工具短响应不等于无效行动。

对同一任务、同一预算进行配对多次运行，记录模型版本及采样设置，打乱运行顺序。用任务作为聚类单位估计置信区间，不能把同一道题的重复运行当成完全独立样本。正式分析前锁定主要指标及超时处理，报告所有组而非最佳种子。

## 建议消融（主实验可运行后再增加）

去掉证据来源约束；去掉状态条件；只选当前最可能假设对应的测试；用信息增益但不考虑成本；强制同等计算预算。

不要第一天就做全部消融。先判断 C 相对 B 是否有值得解释的效果，再增加必要组别。

## 安全和资源边界

只能操作明确授权、隔离、可恢复的靶场。后续真实适配器必须实施网络出站隔离、精确目标白名单、重定向校验、工具白名单、超时和费用控制。网页内容是待分析数据，不得变成系统指令。不得复用真实用户账户或生产数据。

当前代码无网络工具、无自动环境部署，不启动真实攻击，不访问模型服务。外部 Planner 进程是用户信任的程序，不是 OS 沙箱；只有在明确配置后才执行。

## 阶段退出条件

1. 软件原型：测试通过、日志可追溯、预算/失败路径可检查。
2. Pilot：真实模型 + 少量授权任务 + 独立验证器 + 完整成本日志能闭环。
3. 主实验：冻结版本、任务分组、预算及指标后执行配对实验。
4. 研究报告：方法、结果、负例、局限和复现说明齐备。
5. 简历：只使用已完成阶段的事实，结果必须能追溯到日志。

## v0.3 Pilot 预先登记（2026-09-23，写于结果产生之前）

本节在 `results/llm_pilot_v03` 与 `results/web_ablation_v03` 产生任何结果之前写入。manifest 中的源码哈希为 `3364da44…`，LLM 预测表 `results/elicitation_v03/elicitation.json` 的 SHA256 为 `f3b25eca…`。

**环境。** 自建本地 Web 诊断靶场（`hesp/webapp.py`），仅监听 127.0.0.1，每回合新实例。8 种隐藏原因 × 3 种变体（base / drift / noise）= 24 个任务。任务与答案在代码中可见，因此它只能用于 Pilot 与工程验证，**不是**隐藏测试集，也不是 Web CTF。

**LLM Pilot。** 模型 `qwen2.5:7b-instruct`（Q4_K_M，本地 Ollama），温度 0.2，每次调用不同种子。5 个 arm × 24 任务 × 2 次重复，配对、按种子打乱顺序。预算：10 次工具调用 / 10 成本单位 / 12 次决策。

- 主要比较：`hesp − memory_only`（验证完成率，按任务聚类的配对差与 bootstrap 区间）。
- 次要比较：`hesp − react_style`；`memory_only − react_style`；`hesp − hesp_random`（区分“控制器代选动作”与“按 EIG 选动作”）；`hesp − hesp_llm_pred` 与 `hesp_llm_pred − memory_only`（预测表来源的影响）；成本差。
- 判读：24 个任务聚类的区间只描述这一小型靶场；即使区间不含 0，也只写“在本 Pilot 中观察到”，不写“显著优于”。失败、超时、格式错误全部留在分母。

**脚本消融。** 同一个无模型策略（后验 ≥ 0.9 且有当前状态支持证据时结束），只改变选择规则：sequential / eig_cost / eig / map_greedy / random / eig_cost_llmP。工具预算扫描 {2,3,4,5,6,8,10}，每任务 5 次重复。它只回答“在给定预测模型下，选择规则本身的影响”，不涉及 LLM 行为。

**已知局限（事先声明）。** 设计者预测表与靶场生成器几乎一致（KL≈0.01 bit），相当于接近 oracle 的预测模型，会高估 HESP 在真实环境中的收益；LLM 抽取的预测表用来衡量这一差距。假设集合由任务提供，尚未实现开放式假设生成与扩展。

## v0.4 预先登记（2026-09-23，写于任何 v0.4 结果产生之前）

**任务。** web-diag（v0.3 开发族，24 任务）+ **upload-diag（新留出族，24 任务，本次主分析）**。upload-diag 在看到任何 v0.4 结果前设计并冻结；它的最优首探针是成本 2 的 dry-run，且只有“排除法”不能通过独立验证器（必须引用直接显示原因的观察）。

**模型。** Qwen2.5-7B-Instruct（bf16）、Qwen2.5-32B-Instruct-AWQ、Qwen2.5-72B-Instruct-AWQ，本地 vLLM（OpenAI 兼容接口，仅 127.0.0.1），温度 0.2，每次调用不同种子。每个模型先自行抽取两族的 `P(o|h,a)` 并冻结。

**9 个 arm。** react_style、memory_only、memory_guard、hesp_eigc、hesp_eigc_guard、hesp_la、hesp_la_guard、hesp_random、hesp_llmp（定义见 `scripts/run_v04_study.py`）。状态守卫：finish 需引用当前状态版本下被账本采用且支持该假设的观察，且当前得分 ≥ 0.8；否则拒绝并作为工具反馈返回。守卫只读取账本，不接触隐藏答案。

**规模。** 每个模型 9 arm × 48 任务 × 3 次重复 = 1296 回合，配对、按种子 2026 打乱。预算：10 次工具调用 / 10 成本单位 / 12 次决策。

**主要终点。** upload-diag 上 `hesp_la_guard − memory_only` 的验证完成率配对差（任务聚类 bootstrap 95% 区间），每个模型分别报告。

**判读。** 3 个模型 × 10 个比较不做多重比较校正，因此只把主要终点作为确认性结论；其余均为探索性描述。区间不含 0 也只描述这两个手工靶场。所有失败留在分母，所有 arm 与模型全部报告。

**冻结。** 运行前提交代码并记录源码哈希；运行期间不修改 `hesp/`（v0.3 中曾因运行中修改源码导致 15 个回合记录的哈希不一致，已作废重跑，此后禁止）。

## v0.6 预先登记（草案，2026-09-24，写于任何 v0.6 结果产生之前）

**状态：已冻结（2026-09-24，正式运行之前）。** 此后只能以勘误方式追加。冻结内容：本节全文（含修订 R-1 至 R-9）；`hesp/` 源码哈希 `dcf1e79e`（最后一次改动 `hesp/` 的提交为 `44fd458`）；四张经验表 SHA256 `emp1 c2eb5ee7`、`emp5 7aa984f1`、`emp20 c7153c61`、`emp100 7019884f`；服务器运行的代码即本冻结提交的树（以 `git archive` 原样导出）。

**动机（RQ3）。** v0.5 的勘误 E-5 指出，本项目至今所有 HESP 结果都依赖一张**接近 oracle 的预测表**：`sandbox.py` 的 `likelihood_table()` 直接调用环境的生成函数 `true_outcome_distribution()` 再做 ε=0.01 平滑。它不泄漏某一回合的隐藏原因，但等于把世界规则交给了控制器。已有的反面参照是模型自抽取表（`hesp_llmp`）：同一族上 7B 从 0.958 掉到 0.417。**这两端之间的现实设定——从观测数据里估计预测表——从未测过，而它决定了整套方法在真实部署中是否可用。**

**因此本次要回答的问题是：** 当预测表只能从有限的开发期观测中估计、而不是从环境生成函数导出时，EIG/cost + 守卫相对结构化记忆的收益还剩多少？需要多少观测才够？

### 预测表的三种来源（本次的唯一自变量）

| 来源 | 定义 |
| --- | --- |
| `designer_table` | 现状：`true_outcome_distribution()` + ε=0.01。**oracle 上界**，仅作参照 |
| `empirical_k` | **本次新增**：只从 k 个开发回合的实际观测计数估计，见下 |
| `llm_elicited` | 模型自行抽取（v0.4/v0.5 的 `hesp_llmp` 做法）。**下界参照** |

**`empirical_k` 的估计口径（运行前固定）。**

1. 开发回合由一个**不含 LLM 的穷举探测脚本**产生：对每个 (原因, 变体) 实例，按固定顺序执行探针目录中的全部探针，记录 `(probe_id, cause, outcome)`。
2. 只使用 **base 与 noise** 变体估计；**drift 变体排除在估计之外**，因为回合中途真因会切换，计数无法对齐。这使估计严格更不充分，方向是保守的。
3. 每个 (probe, cause) 单元格用计数频率 + 与 designer 表相同的 ε=0.01 平滑；未观测到的结果项只拿 ε 份额。
4. **估计代码不得调用 `true_outcome_distribution()`**，这一点由一条单元测试强制。
5. k ∈ {1, 5, 20, 100}，指**每个 (原因, 变体) 的开发回合数**。开发回合的种子空间与评测回合**不相交**（开发种子见下方修订 R-4，评测沿用 2026 派生的单元种子）。
6. 每张表在任何评测回合开始前生成、落盘、记 SHA256，之后冻结。

**必须写进论文的局限。** 开发回合与评测回合来自**同一个生成器**，所以当 k → ∞ 时 `empirical_k` 收敛到 oracle。本次因此**不是**"未知世界"的检验，而是**数据效率**的检验：测的是"要多少观测才够用"，不是"完全不知道规则时行不行"。真正的未知世界留给 RQ4（外部基准）。同理，本次的假设集合仍由任务给定，未知原因不在范围内。

### 实现期修订（2026-09-24，写代码时发现，仍在任何 v0.6 回合之前）

以下修改都在草案期内、任何评测回合开始之前做出，逐条留痕：

- **R-1 · 结构上隔离 oracle。** 测试发现：即使估计器本身不调用 `true_outcome_distribution()`，**构造环境时**也会顺带算出设计者表。因此给 `build_catalog()` / 环境构造加了 `oracle=False` 选项，改用均匀占位表；开发期探测一律用 `oracle=False`。`execute()` 只核对动作身份、从不读似然表，所以探测行为不变。"估计器不得调用生成函数"这条测试现在是在**生成函数被替换成抛异常**的条件下跑通的。
- **R-2 · 瞬时错误不计数。** noise 变体会返回 503。控制器的账本把它当作无效观测丢弃（`invalid_observation`），估计器原先却把它计入分母，会系统性压低各结果项的概率。现改为与控制器一致：无效观测不计数，另记 `skipped_invalid_observations`。
- **R-3 · k 档嵌套抽样。** 原稿未规定各 k 档是独立抽样还是嵌套。现定为**嵌套**：k=20 的样本恰好是 k=100 样本的前 20 个回合。这样数据效率曲线只反映数据量，不混入各档之间的抽样噪声。
- **R-4 · 开发种子公式。** 为支持 R-3，种子由 `900000 + i` 改为 `900000 + (原因序号 × 2 + 变体序号) × 1000 + i`（i 从 1 起，k < 1000）。与评测种子不相交由单元测试检查。
- **R-5 · 并发。** 本机 Ollama 用 2 个并发 worker。
- **R-6 · 兜底假设 `other` 的已知不对称（不是修改，是解读须知）。** 假设集合含第 9 项 `other`（未知原因）。开发期里它从不是真因，所以经验表中 `other` 的 10 行**结构上不可观测**，只能是均匀分布；而设计者表给了它有信息量的行（例如 `auth_log` 在 `other` 下 99.5% 为 `none`）。因此表生成报告的"单元格覆盖率 0.889"= 80/90：真实的 80 个单元格从 k=1 起全部覆盖，缺的 10 个全是 `other`。后果：经验 arm 中 `other` 的后验衰减更慢，守卫的 0.8 阈值可能需要更多探针。**这是非 oracle 知识的真实代价，部署时同样观测不到未知原因**，解读 oracle 差距时须把这一项单独说明。另：`runbook` 的结果词表只有 `generic` 一个值，是设计上无信息的诱饵探针，每次都被观测到。
- **R-7 · 自抽取表以 LF 字节写入。** manifest 记录自抽取表文件的 SHA256，但此前（含 v0.4/v0.5）该文件在 Windows 上以 CRLF 写入，git 归一化为 LF 后第三方校验会失败。现改为显式写 LF 字节。只影响换行符，不影响内容。此修改在冒烟测试之后、正式运行之前做出，起因是提交时 git 的换行警告，**不是冒烟结果**。
- **R-8 · 推理后端改为服务器 vLLM（取代原"模型"一节的本机 Ollama 设定，也取代 R-5）。** 正式运行改在租用的单卡 RTX Pro 6000D 上执行：Qwen2.5-7B-Instruct **bf16**（与 v0.5 的 7B 为同一权重与后端），vLLM，温度 0.2，每次调用不同种子，32 个并发 worker。冒烟测试用的是本机 Ollama Q4_K_M，**因此冒烟与正式运行的模型不同**，这进一步说明冒烟结果不可用于任何比较。即使权重与 v0.5 相同，v0.6 的提示词也已按勘误 E-4 修改，**仍不得与 v0.5 的数字直接比较**。
- **R-9 · 追加 32B / 72B 作为次要结果（原稿将其排除在范围外）。** 在同一次租用中追加 Qwen2.5-32B-Instruct-AWQ 与 72B-Instruct-AWQ，arm、任务、重复次数、预算、预测表完全相同，每个模型各自重新抽取并冻结自抽取表。**主要终点仍只有 7B 上的 `hesp_eigc_guard_emp20 − memory_only`。** 32B / 72B 的全部比较一律为探索性。事先写明要检验的推测：v0.5 中 32B / 72B 即使用自抽取的劣质表也接近满分，故推测**较强模型对预测表来源不敏感**，即它们的 oracle 差距应接近 0；若不成立，照实报告。
