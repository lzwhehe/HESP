## 一次演示实际发生了什么

模拟环境公开的症状是“文档操作失败”。Planner 看不到隐藏原因，候选解释包括会话过期、对象权限限制、工作流锁定及其他原因。初始分数相同。

HESP 根据人工预测表计算候选测试的预期信息增益，跳过不能区分原因的通用帮助查询。在分数相同时采用稳定的动作 ID 排序，这是可复现的程序规则，不是专家偏好。

本次演示先执行 `inspect_other`，得到 `not_matched`，随后执行 `inspect_owner`，得到 `matched`。控制器逐次保存执行前预测、原始观察及相应分数变化。最后策略提交 `owner_policy` 及实际观察 ID，模拟环境独立确认诊断符合隐藏原因。

这解释的是程序闭环，不说明模型会自行想到这些测试。当前候选目录和结果预测都是手工写入的。

## 研究结论

**尚无真实任务上的有效性结论。** 12/12 不能当成论文完成率或简历性能指标，也不能因为 HESP 在手工任务中跳过帮助查询就声称超过现有 Agent。

第一阶段的交付物是可运行的原型和验证基础。下一阶段先接入选定模型，新增模型生成假设/预测接口，并部署独立的授权任务环境。只有正式对照实验能回答方法是否有效。
