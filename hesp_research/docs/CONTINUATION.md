## 下一阶段

| 工作 | 目的 | 验收标准 |
| --- | --- | --- |
| 确认性研究 | v0.4 的最佳配置（EIG/cost + 守卫）属于事后观察 | 在运行前把它登记为新的主要 arm；换新的种子和任务 |
| 第三个任务族（由他人编写） | 留出族是同一作者当天设计的，不够独立 | 设计者不接触 HESP 代码；运行前冻结 |
| 其他模型家族 | 结论目前只基于 Qwen2.5 | 至少再加一个家族的 7B–70B 模型 |
| 开放式假设生成 | 目前假设集合由任务提供 | 模型提出并扩展假设；记录不在原集合里的真因 |
| 守卫与 7B 的交互 | 7B 被拒绝后会反复重提结论 | 对比不同的拒绝反馈措辞，或限制重提次数 |
| 预测校准 | 自生成预测表的 KL 为 0.86–1.76 比特 | 试验自洽采样、少样本示例等抽取方式，并报告校准与任务成功率的关系 |
| **非 oracle 预测（最高优先）** | 现在的预测表由环境真实生成函数平滑而来，是设计者给的近似 oracle | 预测只能来自开发集估计或冻结的模型输出；测试集的生成函数不得进入。oracle 保留为上界 |
| **无 LLM 的诊断基线** | 若固定规则/贪心策略就能解决，复杂方法的必要性不成立 | 加入纯算法基线（固定顺序、纯 EIG 无 planner）与"强约束 Memory-only"，同预算同信息 |
| **随机 arm 重新预登记** | 当前随机对照仍看得到 EIG 排序，不是干净的控制 | 隐藏排序后重跑，只改变动作选择规则，其余上下文完全一致 |
| **安全向指标** | 只报总完成率不足以说明安全价值 | 另报恶意事件误判为良性的比例、错误升级率、证据引用有效性、未决率与调查成本 |

这些工作不会因为工程测试通过就算完成。当前不承诺发表、录用或在真实渗透测试中的能力。

## Git 工作方式

保留所有历史结果；每个研究里程碑作为一次提交，实验写入新的结果目录。功能分支使用描述性名称（例如 `research/v0.4-...`），**不使用 `codex/` 前缀**。每次运行前提交代码并记录源码哈希，**运行期间不修改 `hesp/`**。逐回合日志较大时压缩为 `runs_archive.tar.gz` 再入库。

凭据只能通过本机环境变量或密钥文件提供，不能提交 `.env`、密钥或密码，也不要在聊天中发送。实验原始材料在提交前要检查，确认不含凭据或真实用户数据。
