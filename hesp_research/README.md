## 当前是什么

这是一个从零搭建的、仅使用 Python 标准库的**可运行研究骨架**。它实现调查记录、候选实验、预期信息增益、证据更新、重复防护、状态变化处理、执行日志和独立结果验证。

**当前还不是完成的研究，也不是自动渗透测试工具。** 默认运行的是手工设计的模拟诊断任务与脚本策略，不调用大模型、不访问网站、不包含漏洞利用载荷。模拟成功率不能写成真实 Web CTF 成功率，脚本策略之间的差异不能证明 HESP 比 LLM Agent 更强。

研究问题：在相同基础模型、工具和总预算下，诊断式行动选择能否在结构化记忆之外，进一步改善复杂 Web 任务的有效进展？

## 一分钟运行

Python 3.10+，无需安装依赖。解压后进入本目录：

```bash
python3 -m unittest discover -s tests -v
python3 -m hesp --mode hesp --case owner_policy --output runs/my_first_run
python3 scripts/run_smoke.py --output runs/my_smoke_suite
```

输出目录必须不存在，程序不会覆盖之前的结果。每次运行生成 `events.jsonl`、`result.json` 与 `config.json`。模拟套件包含 4 个原因 × 3 个模式，结果在 `summary.json` 中。

## 三个对照开关

| 模式 | 传给 Planner 的信息 | 行动选择 |
| --- | --- | --- |
| react_style | 目标、工具说明、完整执行历史 | Planner 选择 |
| memory_only | 同上，加结构化假设、业务状态与证据 | Planner 选择 |
| hesp | 同上，加每个候选行动的信息增益与成本 | 控制器选择信息增益/成本最高的合法行动 |

所有模式具有相同的环境、合法工具、预算和精确重复防护。`react_style` 只是接口形态，不是 ReAct 论文的忠实复现。默认的 `ScriptedPlanner` 仅用于连通性测试，且三个模式共用一套顺序，不据此得出方法优劣结论。

## 核心流程

1. 环境返回公开任务描述，独立的评估器保存隐藏答案。
2. Planner/候选生成器提供少量假设和测试。本版使用固定模拟目录，未实现开放式漏洞假设生成。
3. 对每个候选测试预先保存 `P(结果 | 假设, 测试)` 及其来源。本版这些概率来自人工模拟规则，**不是模型置信度或真实世界校准概率**。
4. HESP 计算预期熵下降，再除以工具调用成本。未知工具、越界目标、缺失前提和超预算行动在打分前拒绝。
5. 写入 `prediction_registered` 日志后，才执行工具。
6. 保存原始观察及其来源。对已建模结果更新分数，对未知/无效/旧状态结果保留不确定性，不硬判为反证。
7. 同一目标、测试目的和状态下的重复执行，不重复计入证据。状态版本变化时，本版保守地重置当前分数，历史记录继续保留。
8. Planner 提交诊断后由环境独立验证。高分不等于确认成功。

## 本版限制

- 没有接入真实模型、浏览器、HTTP 靶场或 Docker，也没有真实 CTF 实验结果。
- 互斥候选原因只适用于同一个局部诊断问题，不能把整个网站的 SQLi、XSS 等所有漏洞当成互斥事件。
- 数值更新和信息增益依赖指定的预测模型。真实模型若预测不准，分数再精确也不能证明决策有效。
- 精确去重不是语义去重，状态变化目前采用全量失效策略，而不是细粒度依赖图。
- 模拟任务从代码中可见答案。只做软件测试，不能用它测模型泛化或设计成隐藏基准。
- 默认流程不产生模型 Token。外部模型须报告真实 usage，缺失则记为 unknown，绝不把缺失记为 0。
- 不收集长篇思维链，仅要求短决策理由、可检验预测及证据引用。
