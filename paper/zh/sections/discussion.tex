\section{讨论}
\label{sec:discussion}

\paragraph{局限性} 两个任务家族都是模拟的：探针返回的是来自冻结结果结构的离散结果，而不是日志行。第二个家族去掉了我们自己对原因和结果的选择（原因来自规则作者，结果来自不属于规划器家族的标注模型），但它的结果结构仍是一个 LLM 的判断，而不是观测到的遥测。两个家族都很小（24 和 76 个任务）且几乎是确定性的，开发回合和评估回合在两者中都共用一个生成器。候选原因是给定的，\textit{其他}只是一个剩余项；生成新假设不在本工作范围内，而 \S\ref{sec:mismatch} 表明，开发数据中缺失的原因是控制器最危险的失败。我们的验证器很严格：结论必须引用带有该原因自身特征的观测，因此靠排除法得出的正确结论也算失败。这条规则自初始研究起适用于所有配置，使我们的完成率偏保守，也是控制器侧停止的全部代价。对抗性部分只在一个家族上测试了每种攻击的一种形式：自由文本字段中的一条指令，以及一个被伪造的探针；能伪造两个独立探针的攻击者也能击败非对称证据规则。我们测试了两个模型家族、五种规模、一个温度和一套推理服务栈，公开数据也无法提供真实遥测上的确证（\S\ref{sec:realdata}）。最后，我们自己也犯过错：报错了一个区间、丢失了一项研究的日志、发现过一次排序泄漏到对照组和一次对基线有利的表不对称、两次更正了一个描述性指标的真值，还在一份已冻结的协议中写错了两组权重的来源。附录~\ref{app:errata} 逐条记录了这些问题；它们都不影响任何已证实的主要终点。

\paragraph{安全含义} 对抗性结果区分了攻击者的两种影响。到达模型的文字被结构性地挡住了：\hesp{} 依据结构化结果决定结论，并拒绝账本不支持的结论，因此日志字段中的指令在任何模型上都没有改变结论，而每个自行决定结论的模型都照做了。到达账本的证据则没有被挡住：控制器信任它的探针，而使它高效的性质，即先依据信息量最大的观测行动并尽早停止，恰恰使一条伪造的观测成为决定性的。由此得到两条部署规则。结束守卫应当始终开启，因为没有守卫的小模型会推翻账本（\S\ref{sec:external}）。不作任何处置就关闭事件的结论应当要求独立佐证，用分析师在良性告警上花的时间，换取对单一伪造来源的抵抗力；哪些来源算作相互独立，取决于具体部署，而不是控制器本身。

\paragraph{模型仍然被需要的地方} 当观测以离散结果的形式到达、表来自开发数据时，大部分工作由流程完成：控制器本身完成 0.917 的案例，而放在控制器里的小模型也不比这更好。模型还剩两个角色。第一个是判断证据何时已足够。自己决定何时停止的强模型达到 1.000，因为它们会等待确认性特征；这种判断也可以写进控制器，成为一条考虑成本的停止规则。第二个是首先把原始数据变成离散观测。真实的探针返回的是日志行，而不是 \textit{high entropy} 这样的标签，把前者变成后者需要阅读。我们的环境自己完成了这一转换，所以我们的结果没有测到这一点。\S\ref{sec:realdata} 中的 OTRF 案例展示了其中涉及什么：识别出任务的创建者是一个人而不是机器账户，或者识别出某次登录来自网络。

\paragraph{设计上的替代方案} 每个设计选择都替换了一个我们实现并测量过的替代方案。在控制器负责选择的前提下，把排序公开给规划器、让它来挑，对完成率的改变不超过 $+0.06$，所以控制器执行自己的选择。一个考虑预算的两步前瞻选择器，在我们开发它的任务家族上比 EIG/成本高 $+0.17$ 到 $+0.21$；但在一个留出的任务家族上（3{,}888 个回合），它与 EIG/成本持平或落后，对 7B 规划器落后 $-0.125$；在 sec-triage 上，它对三个 Qwen 模型的完成率为 0.889、0.972 和 0.958，而 EIG/成本为 0.958、1.000 和 1.000；因此我们保留了贪心规则。向规划器展示超过 0.999 的后验并说明已没有合法探针，并不能让 Llama-3.1-8B 下结论，而由控制器强制执行的停止规则可以。去掉结束守卫时，完成率的变化不超过 $+0.04$，但守卫保证每个被接受的结论都引用了当前的支持性证据，所以我们保留它。

\paragraph{潜在应用} \hesp{} 可以（i）在本地模型上端到端地完成分诊，把每个结论连同所引用的证据和日志交给分析师；或（ii）作为副驾驶，提议下一个探针，并在证据满足接受规则时给出提示。部署时不能把“让控制器来选”当作没有代价：对 Llama-3.1-8B，缺的是停止规则；对 Qwen2.5-7B，停止和探针选择都缺；而对 32B 和 72B 模型，剥夺它们的选择是有害的。预测表是主要的部署成本。在我们的环境中，它们来自同一生成器的开发回合；实践中它们需要来自已结案的工单、专家估计，或经数据校正的 LLM 先验，而其中哪一种足够准确，仍是开放问题。覆盖比精度更重要：在 \S\ref{sec:mismatch} 中，严重扰动的预测表大多导致升级，而开发数据中缺失的原因却导致了自信的（虽然属于同一类别的）错误结论。

\paragraph{运行时间与成本} 端到端延迟主要由 LLM 推理决定；与一次模型调用相比，账本更新和选择的耗时可以忽略。贯穿示例在 8B 模型上做了三次规划器调用，耗时 5.1\,秒；停止研究在五个模型上的 1{,}800 个回合，在一块 GPU 上以 32 个并发回合运行了 28 分钟。控制器选探针还降低了探针成本：在控制器停止下，它把 Llama-3.1-8B 每回合的成本从 4.78 单位减半到 2.35 单位，而无 LLM 控制器的成本是所有配置中最低的。
