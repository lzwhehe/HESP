\section{案例研究：伪装成 Windows 任务的计划任务}
\label{app:case}

OTRF 中唯一确实需要调查的场景，在真实日志上展示了 \hesp{} 所针对的那类案例。它的元数据引用了微软对 Solorigate 入侵的分析~\citep{solorigate}，并把该活动标为远程创建计划任务（T1053.005）。告警是 \texttt{WORKSTATION6} 上的安全事件 4698，报告在文件夹 \texttt{\textbackslash Microsoft\textbackslash Windows\textbackslash Software\-Protection\-Platform} 中新建了任务 \texttt{EventCacheManager}，其文件夹和名字都与真实的 Windows 任务一致；只看文本的规则判定它为良性。第一个探针发现它是域用户 \texttt{THESHIRE\textbackslash pgustavo} 创建的，而 27 份录制中 \texttt{\textbackslash Microsoft\textbackslash Windows} 下的另外 17 个任务事件全部由机器账户创建。第二个探针发现创建它的会话是来自另一台主机的网络登录（类型 3，Kerberos），这排除了本地持久化和用户上下文更新程序。该任务以 SYSTEM 身份运行 \texttt{cmd.exe}，源主机的进程日志显示了创建它的 \texttt{schtasks /create \dots{} /s} 命令。告警文本和调查结果指向相反的方向，两个便宜的探针就能把它们区分开。由于一个探针就足够、而且场景只有这一个，这个案例无法说明探针顺序是否重要；我们只把它作为定性证据。

\section{设计上的替代方案}
\label{app:alternatives}

每个设计选择都替换了一个我们实现并测量过的替代方案。在控制器负责选择的前提下，把排序公开给规划器、让它来挑，对完成率的改变不超过 $+0.06$，所以控制器执行自己的选择。一个考虑预算的两步前瞻选择器，在我们开发它的任务家族上比 EIG/成本高 $+0.17$ 到 $+0.21$；但在一个留出的任务家族上（3{,}888 个回合），它与 EIG/成本持平或落后，对 7B 规划器落后 $-0.125$；在 sec-triage 上，它对三个 Qwen 模型的完成率为 0.889、0.972 和 0.958，而 EIG/成本为 0.958、1.000 和 1.000；因此我们保留了贪心规则。向规划器展示超过 0.999 的后验并说明已没有合法探针，并不能让 Llama-3.1-8B 下结论，而由控制器强制执行的停止规则可以。去掉结束守卫时，完成率的变化不超过 $+0.04$，但守卫保证每个被接受的结论都引用了当前的支持性证据，所以我们保留它。

\section{运行时间与成本}
\label{app:runtime}

端到端延迟主要由 LLM 推理决定；与一次模型调用相比，账本更新和选择的耗时可以忽略。贯穿示例在 8B 模型上做了三次规划器调用，耗时 5.1\,秒；停止研究在五个模型上的 1{,}800 个回合，在一块 GPU 上以 32 个并发回合运行了 28 分钟。控制器选探针还降低了探针成本：在控制器停止下，它把 Llama-3.1-8B 每回合的成本从 4.78 单位减半到 2.35 单位，而无 LLM 控制器的成本是所有配置中最低的。

\section{勘误}
\label{app:errata}

\begin{description}
  \item[E-1] 初始研究曾报告三个主要区间都不含零；实际上 72B 的区间是 $[0.000, 0.236]$。
  \item[E-2] 初始研究的逐回合日志在租用的 GPU 释放之前没有归档。汇总结果可以重算，但第三方无法重新审计原始事件。从表来源研究起，日志都在释放算力之前归档并计算哈希。
  \item[E-3] 初始研究的清单文件中带有来自另一个任务家族早期研究的过时元数据。
  \item[E-4] 在初始研究中，随机选择对照能看到 EIG 排序。分解研究的盲配置消除了这一点。
  \item[E-5] 在表来源研究之前，预测表来自环境的生成器。计数表取代了它们。
  \item[E-6] 描述性安全指标的真值对 drift 回合处理有误，先后更正了两次。现在每个汇总脚本都会检查每个已验证结论是否等于所用的真值。
  \item[E-7] 在表来源研究中，Memory-only 的账本用的是设计者表，而 \hesp{} 用的是计数表。这种不对称对基线有利，因此该研究的主要终点即便有偏差，也只会被低估。分解研究对所有配置都使用计数表。
  \item[E-8] v1.0 的冻结记录称没有使用镜像权重。两个 Llama-3.1 检查点自分解研究起就来自不需要令牌的镜像；它们与此前每项研究使用的是同一批文件。
  \item[E-9] （已披露的偏离。）v1.0 协议原计划在另一块 20\,GB 的 GPU 上标注 Sigma 规则，但 phi-4 放不下。标注改在本研究自己的服务器上进行，使用相同的模型、提示、Schema 与温度，且在任何冻结之前完成；第一台机器没有产生任何标注。
\end{description}
