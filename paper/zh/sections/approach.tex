\section{方法}
\label{sec:approach}

\hesp{}（Hypotheses $\rightarrow$ Evidence $\rightarrow$ State $\rightarrow$ Planning，即假设 $\rightarrow$ 证据 $\rightarrow$ 状态 $\rightarrow$ 规划）是一个位于本地 LLM 规划器和只读探针目录之间的控制器（\cref{fig:pipeline}）。规划器负责提议；控制器决定运行哪个探针、接受哪个结论、调查何时结束。工作流程分两个阶段：
\begin{enumerate}
  \item \emph{建表：}部署之前，无 LLM 的开发运行在起因已知的案例上执行每个探针，\hesp{} 把结果计数成预测表（\S\ref{sec:tables}）。
  \item \emph{调查：}对每条告警，\hesp{} 维护一个假设账本（\S\ref{sec:ledger}），选择要运行的探针（\S\ref{sec:selection}），并对每个结论应用证据规则和停止规则（\S\ref{sec:finish}）。规划器读取账本并提出决策。每一步都在其观测之前写入日志，事后接受审计。
\end{enumerate}

\paragraph{范围与假设} \hesp{} 运行在组织内部网络中，以一个本地开源权重模型作为规划器，并通过固定的探针目录只读地访问安全遥测：认证和 HTTP 日志、来源信誉、DNS 日志、配置、资产清单、变更工单和威胁情报。结论交给人类分析师；智能体从不做修复操作，也从不向被调查的系统发送流量。告警可能由攻击者引起，攻击者控制着智能体所读证据的一部分，例如请求载荷、User-Agent 或命令行，并希望调查以良性结论结束，或根本没有结论。我们信任控制器、它的表、探针实现和日志，不信任规划器会遵循合理的流程。于是，无论规划器输出什么，以下三条性质都成立：（i）每个被执行的探针都在只读目录中、预算负担得起、且在当前状态下尚未运行过；（ii）每个被接受的结论都至少引用一条提高了所声称起因分数的当前观测；（iii）每条预测都在它所预测的观测之前写入日志。这些性质并不保证结论正确，正确与否取决于表以及假设集合是否包含真实起因。特别是，能让某个探针返回良性起因下预期结果的攻击者，仍然可以误导账本；\S\ref{sec:adversarial} 测量了这种情况，以及注入日志内容的指令。生成新假设不在本文范围内。

\subsection{预测表}
\label{sec:tables}
账本和选择器都需要：对每个探针 $a$ 和起因 $h$，给出该探针结果词表上的分布 $P(o \mid h, a)$。\hesp{} 通过计数来估计这些表。一个不涉及任何 LLM 的穷举脚本，在每个起因的每个开发实例上把每个探针运行 $k$ 次，记录结果，并以 $\varepsilon = 0.01$ 平滑归一化计数。这些表在任何评估回合运行之前写入磁盘、计算哈希并冻结；一个单元测试保证估计器从不调用环境的生成函数。实际部署时，开发案例可以来自已结案的工单或重放的事件（\S\ref{sec:discussion}）。

让规划器自己给出似然值可以省去开发数据，但小模型给不出来（\S\ref{sec:rq-help}）。相比之下，在我们的环境中，计数方法每个案例只需五个回合就够用。

\paragraph{示例} 在贯穿示例所用的计数表中（$k{=}20$），探针 \texttt{admin\_exposure} 在管理面板暴露时以 0.995 的概率返回\textit{已暴露、无认证}，在其余七个具名起因下各为 0.005。探针 \texttt{source\_ips} 在撞库下以 0.992 的概率返回\textit{大量住宅 IP}，在其余每个具名起因下为 0.002。

\subsection{假设账本}
\label{sec:ledger}
一个回合从一条告警和一个有限的候选起因集合 $\mathcal{H}$ 开始，其中包含一个显式的\textit{其他}（other）。智能体可以运行只读探针 $a \in \mathcal{A}$，每个探针有成本 $c(a)$，返回有限词表中的一个结果 $o$。预算限制探针数量、总成本、规划器决策次数和墙钟时间。回合以一个结论 $(h, E)$ 结束（$E$ 是被引用的观测集合），或以放弃结束，或以预算耗尽结束。若 $h$ 是当时生效的起因，且 $E$ 中包含一条只有该起因才会产生的当前观测，则结论正确。

账本保存 $\mathcal{H}$ 上的后验 $p(h)$，从均匀先验开始。观测到探针 $a$ 的结果 $o$ 后，它用冻结的表应用贝叶斯规则，并对每个起因记录这条观测是提高、降低还是没有改变它的分数（\textit{支持}、\textit{反对}、\textit{中性}）。暂时性故障（如 HTTP 503）会被记录，但不算证据，该探针可以重试。在所有起因下都不可能出现的结果标志着表冲突，会被跳过。环境暴露一个\emph{状态版本}。当事件在智能体调查过程中发生变化时，版本号递增，当前分数重置为先验；较早的证据仍保留在记录中，但不再算作当前证据。

\paragraph{示例} 贯穿示例的告警报告认证失败和 HTTP 错误激增，此时九个候选各为 0.111。第一个探针 \texttt{source\_ips} 返回\textit{正常}，四个起因仍然可能，各为 0.238。第二个探针 \texttt{access\_pattern} 也返回\textit{正常}，剩下三个各为 0.327：暴露的管理面板、有漏洞的组件、DNS 命令与控制。第三个探针 \texttt{admin\_exposure} 返回\textit{已暴露、无认证}，把暴露的管理面板推到 0.966。

\subsection{探针选择}
\label{sec:selection}
对每个合法探针（当前状态下未试过、预算负担得起、前置条件已满足），控制器计算期望信息增益
\begin{align*}
\mathrm{EIG}(a) &= H(p) - \textstyle\sum_{o} P(o \mid a)\, H\big(p(\cdot \mid o, a)\big),\\
P(o \mid a) &= \textstyle\sum_h p(h)\, P(o \mid h, a),
\end{align*}
其中 $H$ 是香农熵，$p(\cdot \mid o, a)$ 是观测到 $o$ 之后的后验。它按 $\mathrm{EIG}(a)/c(a)$ 为探针排序，并执行第一名，不论规划器提议的是什么。

\paragraph{规划器设计} 每一步，规划器收到一个渲染成文本的结构化请求：任务、候选起因、带成本和结果说明的探针目录、已有观测、账本、被拦截提议的反馈，以及剩余预算（附录~\ref{app:prompt} 原样给出一个例子）。它返回一个 JSON 决策：\texttt{action}（提议一个探针）、\texttt{finish}（一个起因加上所引用观测的 ID）或 \texttt{stop}（放弃）。无效回复会连同错误信息返回给模型，允许重试一次。我们评估的各配置区别在于是否向规划器展示控制器的排序。\emph{盲}配置只说明由控制器挑选探针，既不展示排序也不展示选择器，因此无论运行哪个选择器，提示都完全相同，这一点由单元测试检查。\emph{随机}选择器在合法探针中均匀挑选，作为对照。

\paragraph{示例} 在贯穿示例中，Llama-3.1-8B 在它的三次决策中都提议了 \texttt{auth\_log}。排序在第一步之前把这个探针估为每成本单位 0.51 比特（\texttt{source\_ips} 为 1.74），在第三步之前估为 0.04，而那时 \texttt{admin\_exposure} 以 0.86 领先。控制器实际运行的是 \texttt{source\_ips}、\texttt{access\_pattern} 和 \texttt{admin\_exposure}。

\subsection{证据规则、停止与验证}
\label{sec:finish}
\paragraph{状态守卫的结束} 规划器的 \texttt{finish} 只有在所声称起因的当前分数至少为 $\tau = 0.8$、且至少一条被引用观测是支持它的当前状态证据时才被接受。被拒绝的结束请求会作为反馈返回给规划器。

\paragraph{控制器侧停止} 控制器也可以自行下结论。在每次调用规划器之前，以及预算耗尽时，它对当前领先者应用同一条接受规则。如果规则满足，它引用至多三条支持性的当前状态观测，并结束回合。规划器仍可以更早结束或放弃，而它的提示中没有任何内容透露这条规则。

\paragraph{独立验证器} 只有当所给起因等于当时生效的起因、且至少一条被引用的当前状态观测带有只有该起因才会产生的特征时，结论才算\emph{已验证}。纯靠排除法得到的结论，或仅由多种攻击共有的通用“恶意”威胁情报命中支撑的结论，都不算验证通过。规划器无法访问验证器。

\paragraph{日志与审计} 每次规划器请求和决策、每条预测、观测和账本更新，以及验证，都追加写入日志，并且每条预测都在它所预测的探针运行之前写入。每个回合结束后，审计会重放日志，检查事件顺序、观测来源、计数器、预算、引用，以及控制器做出的每个结论是否满足其规则。

\paragraph{示例} 在贯穿示例中第四次调用规划器之前，暴露的管理面板以 0.966 领先，第三条观测支持它，于是控制器下结论并引用了全部三条观测。验证器确认了该结论，因为第三条观测带有暴露面板自身的特征。这个回合用了三个探针、三个成本单位，耗时 5.1\,秒。在控制器选探针相同但没有停止规则的情况下，同一模型在第三步得到同一条观测，却始终没有下结论（\cref{fig:motivating} 第二行）。

\paragraph{良性结论的非对称证据} 良性结论会在不作任何响应的情况下关闭事件，因此它正是攻击者最想要的结论。作为一条可选规则，控制器可以要求：一个良性原因的结论（无论由规划器提出还是由控制器停止得出）必须由来自至少两个\emph{不同}探针的当前观测支撑，并且每条观测都对它有特异支持。一条观测对某个原因有特异支持，是指在预测表中，它的结果在这个原因下的概率至少是任何其他具名原因下的 10 倍。这条规则只用预测表。规则不满足时，控制器继续探测；如果证据始终互相矛盾，后验会移向\textit{其他}，事件被升级给分析师。\S\ref{sec:adversarial} 测量了这条规则的收益与代价。
