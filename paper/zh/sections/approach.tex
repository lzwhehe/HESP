\section{方法}
\label{sec:approach}

\hesp{}（Hypotheses $\rightarrow$ Evidence $\rightarrow$ State $\rightarrow$ Planning）是一个位于本地 LLM 规划器与只读探针目录之间的控制器（\cref{fig:pipeline}）。规划器提出建议；由控制器决定运行哪个探针、接受哪个结论、调查何时结束。工作流程分两个阶段：
\begin{enumerate}
  \item \emph{构建预测表：}部署之前，在原因已知的案例上运行不含 LLM 的开发回合，执行每一个探针，\hesp{} 把结果计数成预测表（\S\ref{sec:tables}）。
  \item \emph{调查：}对每一条告警，\hesp{} 维护一本假设账本（\S\ref{sec:ledger}），选择要运行的探针（\S\ref{sec:selection}），并对每个结论应用证据规则和停止规则（\S\ref{sec:finish}）。规划器读取账本并提出决策。每一步都在其观测之前写入日志，事后接受审计。
\end{enumerate}

\paragraph{威胁模型与信任} \hesp{} 运行在组织内网，以本地开源权重模型作为规划器，通过固定的探针目录只读访问安全遥测：认证与 HTTP 日志、来源信誉、DNS 日志、配置、资产清单、变更工单和威胁情报。结论是给人工分析员的建议，由分析员结案或升级；良性结论的含义是“建议不采取行动而结案”。智能体从不执行处置，也从不向被调查系统发送流量。告警可能由攻击者引起，攻击者希望调查以良性结论或无结论告终，并控制智能体读取的部分证据。我们按攻击者能写什么、谁来读，区分三条通道。\emph{文本}：被复制进日志的自由文本字段（User-Agent、载荷、工单评论、命令行），规划器若看到原始响应就会读到。\emph{证据}：探针的结构化结果——当攻击者控制某个来源报告的内容时（看起来像扫描器的地址、被投毒的信誉源），由账本读取。\emph{读数}：当日志是原始文本、由模型解析时，同样的自由文本字段会到达读取器，而攻击者的文本随每个探针的响应一起同时到达。我们信任控制器、预测表、探针实现和日志，信任固定的规则解析器；不信任规划器会遵循合理的流程，也不信任作为读取器的模型。于是无论规划器输出什么，以下三条性质都成立：(i) 每个被执行的探针都属于只读目录、在预算之内，并且在当前状态下尚未运行过；(ii) 每个被接受的结论都至少引用一条提高了所称原因分数的当前观测；(iii) 每条预测都在它所预测的观测之前写入日志。这些性质还依赖四条假设：候选原因互斥，且其中之一（可能是 \textit{other}）正在生效；环境会报告事件何时变化（状态版本）；预测表是在与待分诊案例相似的案例上估计的；攻击者无法改动探针实现或日志。这些性质并不保证结论正确——结论是否正确取决于预测表以及假设集合是否包含真实原因——也不涉及证据通道和读取通道，后两者由 \S\ref{sec:evidence} 与 \S\ref{sec:rawlog} 测量。生成新假设不在本文范围之内。

\subsection{预测表}
\label{sec:tables}
账本和选择器都需要：对每个探针 $a$ 和原因 $h$，给出该探针结果词表上的分布 $P(o \mid h, a)$。\hesp{} 通过计数来估计这些表。一个不含 LLM 的穷举脚本，在每个原因与变体的 $k$ 个开发回合中把每个探针各运行一次，并估计
\[\widehat P(o \mid h, a) = \frac{q_{h,a,o}}{\sum_{o'} q_{h,a,o'}},\; q_{h,a,o} = (1-\varepsilon)\,\frac{n_{h,a,o}}{n_{h,a}} + \frac{\varepsilon}{|O_a|},\]
其中 $\varepsilon = 0.01$，$n_{h,a,o}$ 为结果 $o$ 的有效观测数，$n_{h,a}$ 为其总数，$O_a$ 为探针 $a$ 的结果词表；瞬时故障不计入。没有开发回合的原因（如 \textit{other}）得到均匀行。$k$ 按原因和变体计，因此 sec-triage 上 $k{=}20$ 共对应 320 个开发回合。预测表在任何评测回合运行之前写入磁盘、计算哈希并冻结，一个单元测试保证估计器从不调用环境的生成函数。实际部署时，开发案例可以来自已结案的工单或回放的事件（\S\ref{sec:discussion}）。

让规划器直接给出似然可以省去开发数据，但小模型给不出来（\S\ref{sec:rq-help}）。相比之下，在我们的环境中，每个案例只需五个回合，计数就够用了。

\paragraph{示例} 在运行示例所用的计数表（$k{=}20$）中，探针 \texttt{admin\_exposure} 在管理面板暴露时以 0.995 的概率返回 \textit{exposed, no auth}，在其余七个具名原因下各为 0.005。探针 \texttt{source\_ips} 在撞库攻击下以 0.992 的概率返回 \textit{many residential}，在其余具名原因下各为 0.002。

\subsection{假设账本}
\label{sec:ledger}
一个回合从一条告警和一个有限的候选原因集合 $\mathcal{H}$ 开始，其中包含显式的 \textit{other}。智能体可以运行只读探针 $a \in \mathcal{A}$，每个探针有成本 $c(a)$，结果 $o$ 取自有限词表。预算限制探针数量、总成本、规划器决策次数和墙钟时间。回合以结论 $(h, E)$（$E$ 为引用的观测集合）、弃权或预算耗尽结束。若 $h$ 是正在生效的原因，且 $E$ 中包含一条只有该原因才会产生的当前观测，则结论正确。

账本在 $\mathcal{H}$ 上保存后验 $p(h)$，从均匀先验开始。观测到探针 $a_t$ 的结果 $o_t$ 之后，按贝叶斯规则更新 $p_t(h) \propto p_{t-1}(h)\, \widehat P(o_t \mid h, a_t)$，即假设在给定原因时各观测条件独立（\S\ref{sec:mismatch} 测试了违反这一假设的情形），并对每个原因记录这条观测是提高、降低还是没有改变其分数（\textit{support}、\textit{against}、\textit{neutral}）。瞬时故障（如 HTTP 503）会被记录，但不作为证据，该探针可以重试。由于平滑使词表内每个结果都有正概率，只有解析器无法映射到词表的响应才会被跳过；它会被写入日志、不计入，并触发重新规划信号，而不是被静默丢弃。下文使用的后验阈值 0.8 只是这一模型内部信念的性质，不是经过校准的正确率保证（\S\ref{sec:mismatch} 报告了其他阈值）。环境提供\emph{状态版本}，这是一条很强的假设，它免去了检测变化的问题。当事件在智能体调查期间发生变化时，版本号递增，当前分数重置为先验；早先的证据保留在记录中，但不再算作当前证据。

\paragraph{示例} 运行示例的告警报告认证失败和 HTTP 错误激增，此时九个候选各为 0.111。第一个探针 \texttt{source\_ips} 返回 \textit{normal}，剩下四个原因各为 0.238。第二个探针 \texttt{access\_pattern} 也返回 \textit{normal}，剩下三个各为 0.327：暴露的管理面板、有漏洞的组件和 DNS 命令与控制。第三个探针 \texttt{admin\_exposure} 返回 \textit{exposed, no auth}，把暴露的管理面板提升到 0.966。

\subsection{探针选择}
\label{sec:selection}
对每个合法探针（即在当前状态下未运行过、在预算之内且前置条件满足），控制器计算期望信息增益
\begin{align*}
\mathrm{EIG}(a) &= H(p) - \textstyle\sum_{o} P(o \mid a)\, H\big(p(\cdot \mid o, a)\big),\\
P(o \mid a) &= \textstyle\sum_h p(h)\, P(o \mid h, a),
\end{align*}
其中 $H$ 为香农熵，$p(\cdot \mid o, a)$ 为观测到 $o$ 后的后验。控制器按 $\mathrm{EIG}(a)/c(a)$ 对探针排序并执行排名第一者，无论规划器提议了什么。

\paragraph{规划器设计} 每一步，规划器收到一个渲染成文本的结构化请求：任务、候选原因、带成本和结果说明的探针目录、已有观测、账本、被拦截提议的反馈以及剩余预算（附录~\ref{app:prompt} 原样给出一个例子）。它返回一个 JSON 决策：\texttt{action}（提议一个探针）、\texttt{finish}（一个原因及其引用的观测 ID）或 \texttt{stop}（弃权）。无效回复会连同错误信息返回给模型，允许重试一次。我们评测的各配置区别在于规划器是否能看到控制器的排序。\emph{盲}配置只说明由控制器选择探针，既不展示排序也不展示选择器，因此无论运行哪个选择器提示都完全相同，这一点由单元测试检查。\emph{随机}选择器在合法探针中均匀选择，作为对照。

\paragraph{示例} 在运行示例中，Llama-3.1-8B 在三次决策中都提议 \texttt{auth\_log}（每单位成本 0.51 比特）；控制器实际运行的是 \texttt{source\_ips}（1.74）、\texttt{access\_pattern} 和 \texttt{admin\_exposure}。

\subsection{证据规则、停止与验证}
\label{sec:finish}
\paragraph{状态守卫的结束} 只有当所称原因的当前分数不低于 $\tau = 0.8$，且至少一条被引用的观测是支持它的当前状态证据时，规划器的 \texttt{finish} 才被接受。被拒绝的结束会作为反馈返回给规划器。

\paragraph{控制器侧停止} 控制器也可以自行给出结论。在每次调用规划器之前以及预算耗尽时，它对当前领先原因应用同一接受规则。若规则满足，它引用最多三条支持性的当前状态观测并结束回合。规划器仍可以更早结束或弃权，且其提示中没有任何内容透露该规则。由于停止在每次调用规划器之前检查，规划器无法推迟它：规则一旦满足，就不会再询问规划器。\emph{确认条件停止}（v1.1）进一步要求有一条当前观测\emph{特异地}支持领先原因，即该结果在领先原因下的概率至少是预测表中任何其他具名原因下的 10 倍。它只使用预测表，从不接触隐藏的真实原因，并禁止验证器所拒绝的排除法结论。

\paragraph{独立验证器} 只有当原因等于正在生效的原因，且至少一条被引用的当前状态观测带有只有该原因才会产生的特征时，结论才算\emph{已验证}。纯靠排除法得出的结论，或仅由多种攻击共有的“恶意”威胁情报命中支撑的结论，都不能通过验证。验证器知道隐藏的真实原因，因此它只用于评测：实际部署中没有这样的 oracle，控制器和规划器都看不到它的结果。

\paragraph{日志与审计} 每个规划器请求和决策、每条预测、观测和账本更新以及验证结果都追加写入日志，每条预测都在其所预测的探针运行之前写入。每个回合结束后，审计程序重放日志，检查事件顺序、观测来源、计数器、预算、引用，以及控制器给出的每个结论是否满足其规则。

\paragraph{示例} 在运行示例的第四次规划器调用之前，暴露的管理面板以 0.966 领先，且第三条观测支持它，于是控制器给出结论并引用了全部三条观测。验证器确认了该结论，因为第三条观测带有管理面板暴露自身的特征。该回合用了三个探针、三个成本单位，耗时 5.1\,s。在控制器选择相同但不启用停止的配置中，同一模型在第三步得到了同样的观测，却始终没有给出结论（\cref{fig:motivating} 第二行）。

\paragraph{良性结论的非对称证据} 良性结论会在不采取任何响应的情况下结案，因此是攻击者最想要的结论。作为可选规则，控制器可以要求：良性原因的结论（无论由规划器提出还是由控制器停止得出）必须有来自至少两个\emph{不同}探针的当前观测支持，且每条观测都特异地支持它。一条观测特异地支持某个原因，是指在预测表中，该结果在这个原因下的概率至少是任何其他具名原因下的 10 倍。两个探针未必是两个独立来源，因为它们可能读取同一个上游数据源；因此 v1.1 的变体按\emph{来源组}计数，来源组为每个探针声明（在 sec-triage 中，\texttt{source\_ips} 和 \texttt{threat\_intel} 共用一个 IP 信誉源）。该规则只使用预测表。规则不满足时控制器继续探测；如果证据始终不一致，后验会移向 \textit{other}，案件升级给分析员。\S\ref{sec:evidence} 测量了这条规则的收益与代价。

\paragraph{读取器信任} 当探针返回的是日志文本而不是结构化响应时，由解析器产生账本消费的结果。\hesp{} 记录每条观测由哪个解析器产生、是否可信：按文档格式编写的规则解析器可信，模型不可信。在\emph{读取器信任}规则（v1.3）下，不可信的观测可以更新后验，可以作为需处置原因的确认与佐证证据，但在确认条件停止、佐证和结束守卫中都永远不能作为良性结论的特异性支持。这种不对称对应攻击者的目标：确认攻击的伪造读数只造成一次误升级，确认良性原因的伪造读数则会关闭案件。\S\ref{sec:rawlog} 用一个写进每条日志的攻击者测量了这条规则。
