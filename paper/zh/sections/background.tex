\section{背景}
\label{sec:background}

\paragraph{安全运营中的 LLM 智能体} 安全运营中心（SOC）接收检测器发出的告警，必须逐条判断它是否反映了攻击、攻击涉及了什么。厂商和研究者正在把 LLM 智能体放进这个环节：智能体接收告警，通过工具查询日志或抓包，返回判定或攻击者 IP 等指标~\citep{guide,cortex,sentinelrl}。调查是分析员工作中最耗时的部分，也正是这些智能体要接手的部分：从告警追到相关证据，综合多个弱信号，排除乍看一样的良性解释。

\paragraph{基准} 我们审计四个用于评测这类智能体的公开基准或数据集，选择标准是：较新、公开可得、声称衡量调查而非记忆（\cref{tab:benchsetup}）。\emph{ExCyTIn-Bench}~\citep{excytin} 为 Azure 租户中八个模拟的多阶段事件各建一张告警—实体图，并由图上的路径生成题目：起点告警及其实体作为背景，答案是终点告警的一个实体。智能体通过对约 45 张日志表发 SQL 查询作答；由 GPT-4o 判分，并对中间步骤给部分分。\emph{SIABench}~\citep{siabench} 给智能体一条 Snort 告警及其背后的抓包，问它是真阳性还是误报；35 条告警来自 CIC-IDS2017 数据集~\citep{cicids2017}。\emph{GUIDE}~\citep{guide} 包含来自 Microsoft Defender XDR 的 160 万条真实告警，按事件归入 6.1 千个组织，并由这些组织的分析员标为真阳性、良性阳性或误报。\emph{OTRF Security-Datasets}~\citep{otrf} 是在实验室域中执行 ATT\&CK 技术时录下的主机日志，常被用来构建检测与分诊任务。

\paragraph{贯穿示例} \Cref{fig:example} 是一道 ExCyTIn 训练题。背景描述了一条关于主机上异常计划任务的告警。题目问另一条相关告警中记录的 IP 地址，并且点出了这条告警的名字："Anomaly detected in ASEP registry"。基准由"起点告警 $\rightarrow$ 主机 $\rightarrow$ 终点告警"这条路径生成题目，期望智能体从计划任务告警跳到主机，再从主机跳到相关告警。智能体并不需要这次跳转。在 \texttt{SecurityAlert} 表中按告警名查一次，返回的实体列表中恰好只有一个 IP 地址，即答案。我们把这种从题目直达答案、跳过基准设想之调查的路径称为\emph{捷径}。

\paragraph{捷径为什么在这里重要} 捷径学习在机器学习中已有充分记录：模型利用在基准中恰好能预测标签、在部署中却不成立的线索~\citep{geirhos2020shortcut}；标注痕迹让分类器只看假设句就能完成任务~\citep{gururangan2018artifacts}。安全领域有自己的版本：虚假相关和采样偏差会抬高学习型检测器的结果~\citep{arp2022dos}，CIC-IDS2017 中的标注和生成痕迹也早有报告~\citep{engelen2021cicids}。对 SOC 中的 LLM 智能体，后果很直接：基准成绩是防守方决定能否让智能体关闭告警的证据。如果分数是靠查找一个被点名的告警挣来的，它对真正重要的情形几乎没有说明，即没有任何东西点出答案、攻击者让恶意活动看起来像日常操作的情形。
