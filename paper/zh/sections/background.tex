\section{背景与动机}
\label{sec:background}

\subsection{告警分诊}
分诊针对每条告警判断其原因，以及是否需要响应~\citep{nodoze}。攻击调查要重建完整的攻击过程~\citep{kairos,clouseau}，分诊则以一个结论结束：一个原因及其证据。分析员通过查询环境得出结论，而查询在成本和区分候选原因的能力上各不相同。

设想一条报告 Web 层认证失败和 HTTP 错误激增的告警（\cref{fig:motivating}）。它看起来像凭证填充，但 SQL 注入探测、授权的漏洞扫描、被误判的健康检查，以及暴露在互联网上的管理面板都会产生同样的症状。对头部来源做威胁情报查询可能回答“恶意”，而其中三个原因都会得到这个答案。读取管理面板的配置只需一次便宜的查询，就能立刻判定最后一种解释，但只有始终把这个解释放在视野里的调查者才会运行它。因此，一次调查会反复做两个决定：下一步运行哪个查询，以及证据是否已经足够。

\subsection{小模型在流程上失败}
\label{sec:motivation}
LLM 智能体自己做这两个决定~\citep{react}：每一步，模型读取已有观测，然后调用工具或给出结论。\Cref{fig:motivating} 展示了模型为 Llama-3.1-8B、真实原因为暴露的管理面板时会发生什么。当模型选择探针并决定何时停止时（第一行），它从未运行那个决定性的查询。当控制器选择探针、但仍由模型决定何时停止时（第二行），模型在第三步看到了决定性观测，却继续探测直到预算耗尽。只有控制器也负责停止时，回合才以正确的结论结束。

  \centering
  \includegraphics[width=\textwidth]{fig_motivating.pdf}
  \caption{选择探针与停止是两种独立的失败。一条告警（真实原因：暴露的管理面板）、一个本地模型（Llama-3.1-8B）、四种分工方式。每个标签是一次运行的探针（虚线：被控制器拦下的重复提议）；红色标出确认原因的观测。由模型决定何时停止时（前两行），它拿到了决定性证据却继续探测。控制器侧停止会给出结论（后两行），信息增益选择只用三个探针就到达那里。所有行均取自归档日志。}
  \label{fig:motivating}
\end{figure*}

这一模式不只出现在这条告警上。自行选择探针的 Qwen2.5-7B 只解决 8\% 到 13\% 的案例，却几乎花光整个预算，均匀随机选择探针反而更好。Llama-3.1-8B 在全部 3{,}389 次决策中都要求再运行一个探针，包括账本后验已超过 0.999 的决策。更大的模型会给出结论，但没有账本时，Qwen2.5-32B 和 72B 的引用中有 22\% 到 31\% 是无效证据。于是，两个规模相近的小模型失败在不同地方，一个失败在选择探针，一个失败在停止（\S\ref{sec:utility}），这就是为什么控制器必须两个决定都接管，而不是只修补其中一个。

\subsection{攻击者书写的证据}
读取检索内容的智能体会被其中隐藏的指令操纵，即间接提示注入~\citep{greshake2023}，AgentDojo 在工具型智能体上对此做了基准测试~\citep{agentdojo}。通过未转义的用户可控字段实施的日志注入是同一问题更早的形式~\citep{owasp_loginjection}，LogInject 则表明 SOC 中的 LLM 日志分析会以很高的比例服从这类载荷~\citep{loginject}。防御分为两类。模型层面的防御，如结构化查询和偏好优化~\citep{struq,secalign}，降低但不能消除模型服从注入文本的倾向。系统层面的防御把有特权的规划器与不可信数据分开：Dual LLM 模式和 CaMeL~\citep{camel}让一个隔离的模型读取数据、由规划器固定控制流，CaMeL、FIDES~\citep{fides} 和 Progent~\citep{progent} 则对随后的工具调用施加策略。CaMeL 也指出，隔离的读取器仍是一条通道：无法改变计划的攻击者，仍能决定读取器返回的值。在分诊中，这条通道就是攻击的全部，因为结论正是从读取器返回的值算出来的，之后没有任何可供策略拦截的工具调用。
