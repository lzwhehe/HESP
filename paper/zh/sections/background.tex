\section{背景}
\label{sec:background}

\subsection{告警分诊}
告警分诊紧随检测之后：对每条告警，分析员要判断实际发生了什么、是否需要响应~\citep{nodoze}。攻击调查从一个关注点出发重建完整的攻击过程~\citep{kairos,clouseau}；分诊则以单一结论结束，即告警的原因及支持它的证据。分析员通过查询环境得出结论。不同查询的成本不同，区分候选解释的能力也不同。有些查询代价低，对某一种解释有决定性作用；另一些（如威胁情报查询）速度慢，而且对几种攻击返回相同的答案。因此，查询顺序决定了调查多快结束，分析员还必须判断证据何时已经足够。

设想一条告警报告 Web 层的认证失败和 HTTP 错误激增。它看起来像撞库攻击，但同样的症状也可能来自 SQL 注入探测、授权的漏洞扫描、被误判为攻击的健康检查，或暴露在公网上的管理面板。对头号来源做威胁情报查询可能会返回“恶意”，而这个答案三种原因都会给出。读取管理面板的配置只需一次低成本查询，就能立刻确认或排除最后一种解释，但只有始终把这种解释放在视野中的调查者才会去运行它。

\subsection{本地 LLM 智能体}
LLM 智能体把语言模型与工具结合起来：每一步，模型读取任务和已有观测，然后调用一个工具或结束任务~\citep{react}。Qwen2.5、Llama~3.1 等开源权重模型可以运行在组织自己的硬件上（4 比特权重下，单卡最多可运行 72B 参数），遥测数据不出本地，但循环中的每一步都依赖于一个较弱的模型。
