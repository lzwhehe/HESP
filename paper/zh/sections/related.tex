\section{相关工作}
\label{sec:related}

\paragraph{用于调查与分诊的 LLM 智能体} 研究 LLM 智能体如何调查安全告警的工作很少，据我们所知，没有一项测量过往证据里写东西的攻击者能做到什么。Clouseau~\citep{clouseau} 用一组自行选择查询的分层 LLM 智能体从事件日志重建攻击叙事，并报告开源权重模型在复杂场景上落后于专有模型；其作者指出，叙事重建超出了分诊的需要，因为分诊追求的是快速的接受或升级决定。ExCyTIn-Bench~\citep{excytin}、GUIDE~\citep{guide} 和 Cyber Defense Benchmark~\citep{cyberdefensebench} 为调查和威胁狩猎提供数据，它们与本问题的契合度见 \S\ref{sec:realdata}。据我们所知，本研究首次把攻击者触及分诊智能体结论的路径定位为“模型掌握哪些决定”的函数；对每条路径，我们都在五个模型上测量了攻击，给出了关闭它的规则，并测量了规则的代价。

\paragraph{针对工具型智能体的攻击与防御} Greshake 等人~\citep{greshake2023}展示了间接提示注入，即隐藏在检索内容中的指令劫持集成 LLM 的应用；AgentDojo~\citep{agentdojo} 在工具型智能体上对这类攻击与防御进行了基准测试；通过未转义的用户可控字段实施的日志注入是同一问题更早的实例~\citep{owasp_loginjection}。保护智能体的工作约束智能体能做什么：IsolateGPT~\citep{isolategpt} 隔离 LLM 应用的执行，Progent~\citep{progent} 对工具调用施加权限策略。在 ReAct~\citep{react}、Reflexion~\citep{reflexion} 和 Toolformer~\citep{toolformer} 等通用工具型智能体中，由模型决定下一步做什么、何时结束。\hesp{} 同样认为智能体应当在模型之外受到约束，但分诊智能体只读不写，所以它约束的是结论（运行哪个探针、接受哪个结论、何时停止、哪些读数可以支持良性结论），而不是访问权限。

\paragraph{基于溯源的分诊} 基于溯源的系统构建主机活动的因果图，并用规则或学习模型使其易于处理：NoDoze~\citep{nodoze} 依据告警周围溯源的异常程度对告警排序以缓解告警疲劳，Kairos~\citep{kairos} 从全系统溯源中检测并重建入侵。这些系统决定分析员应该看什么，而不是下一步运行哪个查询；\hesp{} 针对的正是这下一步及其后的结论。

\paragraph{序贯诊断} 按期望信息增益选择测试可以追溯到 Lindley~\citep{lindley1956} 和贝叶斯实验设计~\citep{chaloner1995}。它是经典基于模型的诊断~\citep{dekleer1987}的基础，并对贪心主动学习和含噪假设识别具有近似最优保证~\citep{dasgupta2004,golovin2010}。我们原样使用这一教科书准则，研究它如何与 LLM 规划器相互作用；语言模型在某些自我评估任务上可以是校准的~\citep{kadavath2022}，但我们向模型询问得到的表表明，这并不适用于探针结果的似然。预注册把验证性分析与探索性分析分开~\citep{nosek2018}，基于机器学习的安全评测中的陷阱已有充分记录~\citep{arp2022dos}；我们两者都遵循。
