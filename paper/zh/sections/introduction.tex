\section{引言}
\label{sec:intro}

安全运营面临一个日益加剧的张力：告警的数量与可用于解释它们的分析员时间不成比例——大多数告警最终证明是良性的~\citep{nodoze}，但每一条在关闭之前都必须追溯到原因。为缓解这一张力，人们把分诊自动化，以便对每条告警判断其原因是攻击、配置错误、授权活动还是误报。这类自动化的两个典型例子是基于溯源的排序~\citep{nodoze,kairos}和 LLM 调查智能体~\citep{excytin,clouseau}。基于溯源的系统构建主机活动的因果图并对其排序或摘要，让分析员少读一些；但它们决定的是分析员该看什么，而不是下一步运行哪个查询，结论仍留给分析员。LLM 调查智能体以 ReAct 模式~\citep{react}选择查询并读取结果，但其中最强的依赖托管模型，而许多组织不能或不愿把原始遥测发送给托管模型。

作为把遥测留在本地的替代方案，基于小型开源权重模型的分诊智能体已经变得可行：它们在单块本地 GPU 上运行，自己选择查询，并在没有分析员参与的情况下给出结论。从高层看，这样的智能体接收一条告警和一个只读查询目录，例如认证日志、请求模式、来源信誉、配置、变更工单和威胁情报；每一步，模型读取已有结果，然后要么再运行一个查询，要么给出一个原因及其引用的证据。智能体一旦给出结论，良性结论会在不采取任何响应的情况下关闭案件，其他结论则把案件升级给分析员。

然而，既然这个循环如此依赖模型，我们几乎不知道小型本地模型能多可靠地执行调查流程，也不知道攻击者能在多大程度上左右结论。同样不清楚的是：攻击者能触及模型的哪些决定，模型之外的组件能否接管这些决定，以及这样的组件会损失多少准确性。这些问题之所以重要，是因为分诊智能体读到的内容有一部分是攻击者写的：请求载荷、用户代理、命令行和工单文本都会进入日志，而通过检索内容实施的间接提示注入已有充分记录~\citep{greshake2023,agentdojo}。本文报告一项针对本地 LLM 分诊智能体的受控安全研究，用一个能把每个决定从模型手里拿走的控制器、三个带攻击者的模拟分诊场景、八项在第一个回合之前冻结的研究，以及关闭我们发现的每条路径的规则，回答了这些问题。

我们的研究依靠三个组成部分。首先，我们构建了控制器 \hesp{}，把流程放在模型之外：它维护候选原因的贝叶斯账本，按单位成本的期望信息增益对只读探针排序，只在账本中有当前观测支持时才接受结论，并且可以自行结束调查。其中每个决定都可以交还给模型，因此同一个智能体可以在每一种控制权分配下被研究。其次，为了测量攻击者从哪里进来，我们设计了一个分诊测试床：每个回合在自己的回环沙箱中运行，攻击者往日志字段里写入指令、伪造一个数据来源，或者在模型解析原始日志时针对它。我们审计过的公开数据集缺少客观标注下配对的攻击与相似的管理活动（\S\ref{sec:realdata}），所以测试床提供三个模拟场景：一个原因由我们编写，一个从公开的 Sigma 检测规则机械派生，一个让攻击与合法活动使用相同工具。面对五个模型上的几十种配置，只要去找就总能找到某种效应。为应对这一挑战，每项研究都在第一个回合之前固定了假设、主要终点和源码哈希，并且 23{,}582 个 LLM 回合的日志都经过审计重放。

借助这些组成部分，我们的研究得出了以下发现。

首先，小型本地模型在调查流程本身上失败，而且以两种不同的方式失败。自行选择探针的 Qwen2.5-7B 只有 8\% 到 13\% 的案例以已验证的结论结束，却几乎花光了整个预算；在我们的提示与服务配置下，Llama-3.1-8B 在全部 3{,}389 次决策中都要求再运行一个探针。更大的模型会给出结论，但引用中有 22\% 到 31\% 是无效证据。“探测什么”与“何时停止”是两种独立的失败，所以控制器必须两者都接管（\S\ref{sec:rq-stop}）。

此外，模型决定时，埋在日志字段里的一条指令就能关闭案件。在四种注入文本下，每个自行决定并给出结论的模型都服从了“关闭告警”的指令。只接受账本支持的结论的结束守卫在每个模型上都挡住了它，因为这段文本从未进入账本，注入的效果降为悬而未决的案例（\S\ref{sec:injection}）。

另外，一旦由控制器决定，攻击者必须伪造证据而不是文本，而一个伪造来源就足够了。一条伪造的扫描器答案，或两个探针共同读取的被投毒信誉源，在每个模型上都把 18/18 个需处置案例结为良性，因为控制器先按信息量最大的观测行动。要求良性结论得到两个不同来源组的支持会把它们全部升级，代价是一个场景中 6 个诚实良性案例里的 3 个，另一个场景中 104 个里的 8 个（\S\ref{sec:evidence}）。

更令人担忧的是，留给模型的唯一角色重新打开了攻击。日志格式变化时，规则解析器什么也读不出，每个案例都被升级，因此只能由模型读取日志。于是，往每条日志的自由文本字段里写入一致良性故事的攻击者一次触及所有来源：采纳每条声称的读取器把全部 36 个需处置案例结为授权扫描，Qwen2.5-7B 在变化后的日志格式上也是如此，来源组佐证无济于事。读取器信任规则让模型的读数可以确认攻击、却永远不能确认良性结论，在两个模型上都没有让任何攻击关闭案件（\S\ref{sec:rawlog}）。

最后，在我们的场景中，把决定从模型手里拿走并不损失准确性。采用验证器的证据标准后，控制器单独就能解决三个场景中两个的每一个案例；预先登记的比较没有发现让 Qwen2.5-72B 决定何时停止带来增益，而给基线一个为帮助它们而选出的提示后，它们仍然落后 $+0.667$ 和 $+1.000$。在原因使用相同工具的地方，证据标准以自动化换取安全：联合证据能解决更多案例，但会把 18 个攻击中的 4 个结为与之相似的合法活动（\S\ref{sec:cost}）。

本文的贡献可以概括如下。
\begin{itemize}
  \item 我们对本地 LLM 告警分诊智能体做了一项受控安全研究，定位了攻击者触及结论的三条路径，每条对应一种控制权分配。
  \item 我们设计并实现了 \hesp{}\footnote{代码、冻结协议、预测表、结果文件，以及除第一项研究外（勘误 E-2）每项研究的回合日志见 \repourl。}，一个能把每个分诊决定从模型手里拿走的控制器，以及关闭所发现路径的三条规则：结束守卫、来源组佐证和读取器信任。
  \item 我们构建了一个包含三个模拟场景和五类攻击者的分诊测试床，并在冻结协议下运行了八项研究，附有审计过的日志、每种读取器攻击的脚本上界，以及我们自己错误的记录。
  \item 我们得出了一组有数据支撑的发现：小模型如何在流程上失败，每种攻击在哪里成功、在哪里失败，以及每条规则的代价。
\end{itemize}
