\section{评测结果}
\label{sec:results}

\subsection{可靠性}
\label{sec:rq-help}
初始研究（1{,}944 个回合，设计者表）比较了完整 \hesp{}（EIG/成本选择加结束守卫）与 Memory-only（规划器看到同样的账本，但自己选探针）。已验证完成率在 Qwen2.5-7B 上提高 $+0.889$ $[+0.75,+1.00]$，在 32B 上提高 $+0.250$ $[+0.10,+0.42]$。在 72B 上增益为 $+0.111$，区间触及零（$[0.000,+0.236]$）。增益随模型规模缩小，符合预期。由于该研究的预测表来自环境生成器，留下了一个问题：增益是否依赖 oracle 知识？表来源研究用计数表替换设计者表，以 7B 相对 Memory-only 的比较作为唯一主要终点。\cref{tab:v06} 报告了每种预测表来源下的已验证完成率。

有三点发现。第一，计数表与 oracle 相当。用每个原因和变体 $k{=}20$ 个开发回合计数得到的表，\hesp{} 把 Qwen2.5-7B 从 0.125 提升到 1.000（$+0.875$ $[+0.74,+0.97]$；22 个任务更好，没有任务更差），三个模型上的完成率都与设计者表相同。$k{=}5$ 时已经饱和，$k{=}1$ 时每个模型至多损失一个回合。这种饱和反映的是环境几乎是确定性的，而不是一般意义上的数据效率。

第二，计数表比设计者表每个回合多花 1.2 到 2.4 个探针成本单位；一次不含 LLM 的检查把全部差距定位到 \textit{other} 这一行，也就是开发数据中从未出现过的那个原因。

第三，模型无法自己写出预测表：用规划器给出的表时，7B、32B、72B 的完成率降到 0.069、0.375 和 0.375，因此控制器既要提供流程，也要提供表中的知识。

\subsection{排序与选择权}
\label{sec:rq-rank}
由控制器选择探针同时改变了两件事：拿走了模型自己的选择权，并用一个排序取代了它。分解研究用盲配置把两者分开（无论用哪个选择器，规划器收到的提示都相同），并加入了 Llama~3.1 家族。它的主要终点是 Qwen2.5-7B 上的排序效应（盲 EIG/成本对盲随机），以及 Llama-3.1-8B 上完整 \hesp{} 对 Memory-only。附录~\ref{app:tables} 中的\cref{fig:decomposition} 给出了每个模型上增益的两个组成部分。

有三点发现。第一，排序本身有用。在规划器信息完全相同的情况下，EIG/成本选择在 Qwen2.5-7B 上比随机选择高 $+0.306$ $[+0.14,+0.47]$，第一个主要终点成立。在每个会给出结论的模型上效应都相近：Qwen 32B、Qwen 72B 和 Llama 70B 上分别为 $+0.35$、$+0.35$ 和 $+0.26$，区间都不含零。

第二，拿走选择权对弱模型有利，对强模型不利。把模型自己的探针选择换成随机选择，7B 模型的完成率提高 $+0.556$（它自己的选择比随机还差），而 Qwen 32B 和 72B 分别降低 0.222 和 0.278（它们的选择优于随机）。向规划器展示排序和加入结束守卫，对完成率的影响都至多 $+0.06$。

第三，由控制器选探针并不能让模型给出结论。第二个主要终点不成立。在我们的提示和服务配置下，Llama-3.1-8B 在本研究的任何配置中都没有完成 360 个回合中的任何一个：它做了 3{,}389 次决策，全部是请求下一个探针，输出始终是合法 JSON。控制器决定了探测什么，但何时停止仍由规划器决定。

\subsection{探测与停止}
\label{sec:rq-stop}
停止研究把“谁选探针”与“谁可以停止”交叉，加入随机选择对照，并把两个主要终点都放在 Llama-3.1-8B 上：控制器停止能否挽救它，以及在提供停止之后控制器选择是否仍有帮助。不含 LLM 的模拟事先预测第一个终点约为 0.9，因此第二个终点才是真正有信息量的检验。\cref{fig:probe-stop} 报告了结果，附录~\ref{app:tables} 的\cref{tab:v09} 列出每一格。

\begin{figure*}[t]
  \centering

  \caption{停止研究：按谁选探针、谁可以停止给出的已验证完成率（每点 72 个回合）。虚线是事后运行的不含 LLM 的控制器（EIG/成本选择加控制器停止，种子和任务相同）。}
  \label{fig:probe-stop}
\end{figure*}

第一，控制器停止挽救了从不给出结论的模型。允许控制器停止后，Llama-3.1-8B 从 0 升到 0.917（$+0.917$ $[+0.79,+1.00]$；22 个任务更好，没有任务更差），与预测一致。

第二，对这个模型而言，增益来自停止。提供停止之后，Llama-3.1-8B 自己选探针达到 0.861，控制器选择达到 0.917，差值为 $+0.056$ $[-0.07,+0.18]$。区间允许存在中等的收益，因此我们只能说：对这个模型，选择没有带来可检测的完成率提升。选择确实让探针成本减半（2.35 对 4.78 个单位）。模型自己的选择与固定的目录顺序表现相当，后者在不含 LLM 的运行中以 4.85 个单位达到 0.847。

第三，小模型的失败方式各不相同。仅控制器停止就把 Qwen2.5-7B 从 0.083 提升到 0.694，控制器选择再增加 $+0.222$ $[+0.08,+0.39]$（附录~\ref{app:tables}）。因此它在分解研究中的失败，一部分是拒绝下结论，一部分是探测不当；而 Llama-3.1-8B 的失败几乎完全是拒绝下结论。控制器事先无法知道某个模型缺的是哪一部分，所以两部分都得提供。

第四，在控制器停止下，排序效应在全部五个模型上都得到重复（$+0.17$ 到 $+0.21$，区间不含零）。

第五，后验停止会依靠排除法下结论。在本来就会下结论的模型上，允许控制器停止会使完成率降低 0.01 到 0.08。在控制器选择加停止的配置中，四个模型的失败都是同样的六个回合：控制器通过排除其他可能得出正确的 DNS 命令与控制结论，但验证器因缺少确认特征而拒绝，这一点协议事先已经预料到。Qwen2.5-72B 除这六个外还多三个：漂移回合中它抢先结束，在监控误报生效时给出了 SQL 注入。在不启用控制器停止的配置中，由 Qwen 32B 和 Llama 70B 决定何时停止时，它们会一直探测到 DNS 证据出现，并完成全部案例。

最后，控制器单独运行已经很接近。不含 LLM 的运行以 2.35 个单位完成 0.917 的案例，是所有配置中成本最低的。当控制器既选探针又停止时，五个模型中有四个也恰好得到 0.917、成本相同，说明模型在这里几乎没有贡献。胜过它的配置都是由强模型决定证据何时足够，而它们的优势来自比后验停止更严格的证据标准。\S\ref{sec:fair} 让控制器也采用这一标准。

\subsection{相同证据标准}
\label{sec:fair}
上面的比较混在一起的是两件事：LLM 是否有帮助，以及用什么证据标准结束回合。后验停止接受排除法得出的结论，而验证器拒绝这类结论；自行决定何时停止的强模型则会等待确认特征。v1.1 研究消除了这一混杂：它给不含 LLM 的控制器配上 \S\ref{sec:finish} 的确认条件停止，加入固定流程和目录顺序作为更简单的参照，并在两个任务族上以相同的种子、任务和预算运行所有 LLM 配置，全部开启结束守卫。其主要终点在每个任务族上比较“Qwen2.5-72B 决定何时停止”与“不含 LLM 的确认条件停止”（97.5\% 区间）；其他模型为探索性结果。\cref{tab:v11fair} 给出计数。

第一，采用验证器的标准后，控制器单独就能完成每一个案例。EIG/成本选择加确认条件停止在 sec-triage 上验证 72/72、在 sigma-triage 上验证 152/152 个回合，成本分别为 2.54 和 2.20 个单位。此前因排除法而失败的六个 DNS 回合现在都完成了，每个回合只多花 0.19 个单位。在 sec-triage 上自适应选择仍然重要：固定流程只达到 66，目录顺序 65；在 sigma-triage 上则不然，任何顺序都至少完成 152 个中的 151 个。在本研究全部 3{,}968 个不含 LLM 的回合中（包括 \S\ref{sec:mismatch} 的表误差条件），控制器从未把攻击判为良性。

第二，没有任何模型能在这个控制器之上提高完成率。两个主要终点都没有显示增益：Qwen2.5-72B 自行决定何时停止，在 sec-triage 上验证 72/72（$+0.000$ $[0.000, 0.000]$），在 sigma-triage 上验证 148/152（$-0.028$ $[-0.111, 0.000]$），成本分别为 3.86 和 3.25 个单位，而控制器为 2.54 和 2.20。按照运行前写定的判读，我们没有测到 LLM 在停止判断上的增益。其他大模型表现相同：Qwen2.5-32B 和 Llama-3.1-70B 在 sec-triage 上也都是 72/72，在 sigma-triage 上分别为 144 和 145/152，成本最高达 9.0 个单位；三个大模型在 sigma-triage 上的所有未验证回合都是原因正确但缺少确认特征。在确认条件停止下，每个模型在 sec-triage 上都达到不含 LLM 的结果，在 sigma-triage 上除 Qwen2.5-7B（141）外也都如此。由模型决定何时停止时，Llama-3.1-8B 只完成 0 和 1 个回合，Qwen2.5-7B 完成 66 和 126 个。Qwen2.5-7B 在控制器停止下的不足只有一个原因：在三条规则上，它在后验 0.794 到 0.796（略低于守卫阈值）时提出结束，守卫拒绝后它反复提出同样的结束，直到决策预算耗尽（152 个中的 11 个回合，每个被拒绝 9 到 11 次）。控制器停止在 0.8 以下也不会触发。因此规划器可以让带守卫的控制器陷入僵局；若控制器在拒绝结束之后改为运行排名第一的探针，就能避免这种情况，但我们没有修改已冻结的实现。

第三，停止失败在一定程度上是提示造成的。回放 60 个证据压倒性或已无合法探针的归档请求，Llama-3.1-8B 每次都返回合法、未截断的 JSON；在原始提示、带结束示例的提示和明确说明何时必须结束的提示下，分别有 60、60 和 58 次请求探针（chat template 和各项配置已计算哈希并记录）。在 \hesp{} 内的在线回合中，明确规则让它在 48 个中完成 8 个，另外两个变体为 0；对 Qwen2.5-7B，两个变体都把 \hesp{} 内的完成数从 43 提高到 48/48。因此在结构化观测下，控制器解释了我们测试的每个模型上的全部增益。

\subsection{失败模式}
\label{sec:security}
附录~\ref{app:tables} 的\cref{tab:security} 按错误类型分解了表来源研究的结论。这些指标是描述性的，没有预先登记为终点。

使用计数表时，\hesp{} 在全部 216 个回合中都给出了结论，且没有一个原因错误。基线的失败方式随规模而变。7B 基线很少下结论：ReAct 式在 72 个回合中只有 3 个给出结论，Memory-only 为 9 个。更大的 ReAct 式基线会下结论但常常出错：在给出结论的需处置回合中，它们分别把 51 个中的 13 个（32B）和 54 个中的 20 个（72B）判为良性，引用中分别有 22\% 和 31\% 无效。仅账本就消除了大部分错误：Memory-only 分别只把 54 个中的 2 个和 53 个中的 1 个判为良性。在停止研究中，控制器选择加控制器停止的配置在五个模型上都没有把任何需处置事件判为良性。

有三点发现。第一，两个主要终点在第二任务族上都成立。在规划器信息不变的情况下，排序在 Qwen2.5-7B 上增加 $+0.171$ $[+0.094,+0.250]$（24 个任务更好，2 个更差），带控制器停止的 \hesp{} 比 Memory-only 高 $+0.296$ $[+0.088,+0.473]$（32 个更好，2 个更差）。排序效应在全部五个模型上都得到重复，为 $+0.105$ 到 $+0.230$，与 sec-triage 上测得的 $+0.17$ 到 $+0.21$ 接近。

\subsection{预测表误差}
\label{sec:mismatch}
控制器的知识存放在预测表中，而在我们的环境里，预测表与测试回合来自同一个生成器。表误差部分研究这一联系断开时控制器如何失败。它用从不结束的脚本代替 LLM，使每个结论都来自控制器本身，并以四种方式扭曲预测表：只用 base 变体计数、只用一个开发回合、把每一行与随机分布混合（权重 $\lambda$），以及把某个原因从开发数据中去掉。\cref{tab:v10b} 报告了结果；分析是描述性的。

\begin{table*}[t]
  \caption{预测表误差（不含 LLM，后验停止阈值 0.8）。EIG/成本选择下：已验证、原因正确但缺少确认特征、原因错误和升级的回合比例（四者之和为一）；随机选择下：已验证完成率。“扰动”把每一行与随机 Dirichlet(1) 行按权重 $\lambda$ 混合（每个水平 20 张随机表）；“缺失一个原因”对依次从开发数据中去掉每个原因、并在该原因上测试的结果取平均。}
  \label{tab:v10b}
  \centering\small
  \begin{adjustbox}{max width=\textwidth}\input{../tables/v10b_main}\end{adjustbox}
\end{table*}

有三点发现；前两点在两个任务族上都成立。第一，不准确的预测表让控制器安全地失败。随着 $\lambda$ 增大，完成率下降，但失败变成升级而不是错误结论：即使每一行有四分之三是噪声，错因率也不超过 0.009，这与含噪后验很少在单一原因上达到 0.8 阈值相一致。在两个任务族的每个 $\lambda$ 水平上，EIG/成本都领先于随机选择。sigma-triage 退化得更慢（$\lambda = 0.5$ 时为 0.978），因为它的原因有更多可区分的结果。只用 base 变体或只用一个回合计数都没有可测的影响，这反映了环境的确定性。

第二，开发数据中缺失某个原因，是唯一会产生自信的错误结论的误差。此时该原因的行不含信息，本应揭示它的观测会被算作其他某个原因的弱证据。在 sec-triage 上，EIG/成本选择对八个原因中的四个（SQL 注入、DNS 命令与控制、暴露的管理面板和有漏洞的组件）在每个回合都给出错误原因，另外四个则升级。在 sigma-triage 上，38 个原因中有 3 个出现这种情况，其余 35 个升级。在两个任务族的每个错误结论中，所给原因都与真实原因属于同一类：缺失的攻击被认成另一个需处置原因，缺失的良性解释被认成另一个良性解释。在这些测试中，没有任何缺失原因导致攻击被结为良性，但响应会被引向错误方向。在所评测的随机混合扰动下，大多数失败是升级；这些结果并不能证明控制器对任意或对抗性的似然误差具有鲁棒性。

第三，v1.1 研究加入了随机混合产生不了的误差（sec-triage，每格 48 个不含 LLM 的回合）。\emph{系统性混淆}把每个原因的行向某个固定的另一原因混合：权重 0.25 时后验停止几乎不受影响（48 个中验证 47 个），但确认条件停止完全失效——没有任何结果在一个原因下的概率仍是其配对原因的 10 倍，于是全部 48 个回合都耗尽预算并升级。权重 0.5 时，后验停止也有 42/48 升级。两种停止都没有给出错误原因。\emph{候选集合中缺失真实原因}（不只是开发数据中缺失）时，后验停止在 48 个回合中有 24 个给出另一个需处置原因（DNS 命令与控制被认成有漏洞的组件，有漏洞的组件、暴露的管理面板和 SQL 注入被认成 DNS 命令与控制），而确认条件停止把全部 48 个升级。\emph{重复的来源}（第二个探针读取与 \texttt{source\_ips} 相同的数据源）没有可测的代价。阈值在 0.6 到 0.95 之间时，确认条件停止保持 1.000，成本逐步上升（2.54 到 4.14 个单位），而后验停止从 0.9 起降到 0.875。在这 3{,}968 个回合中，控制器从未把攻击判为良性。因此，确认条件规则把自信的错误结论转化为升级，但当预测表混淆两个原因时它很脆弱。

\subsection{对抗性证据}
\label{sec:adversarial}

有三点发现。第一，控制器使注入的指令失效。每个会自行下结论的模型，只要由它决定结论（ReAct 式或 Memory-only），在每个回合都会服从这条指令；Llama-3.1-8B 例外，只是因为它从不下结论。在所评测的注入模板下，带守卫的 \hesp{} 没有在任何需处置案例上给出良性结论（五个模型上都是 18 个中的 0 个）：文本从不进入账本，而守卫会拒绝证据不支持的良性结论。主要终点成立，$+1.000$ $[+1.000,+1.000]$；退化的区间反映的是全部 18 个配对回合方向一致，而不是对其他任务不存在不确定性。注入仍然产生了影响：Qwen 规划器在良性结论被拒绝后放弃了其中 9 到 12 个回合，案件被交给分析员而不是被关闭，但这会占用分析员的时间。

第二，单条伪造观测就能击败目前为止的控制器。在 \emph{spoof} 下，\hesp{} 在五个模型上都把每个需处置案例结为授权扫描，而且只用一个探针。控制器先运行信息量最大的探针，伪造的扫描器回答立刻把授权扫描推过 0.8，控制器停止随即给出结论。在这里，按信息量最大的证据提前停止，恰恰是攻击者所利用的。很少下结论的 LLM 基线反而较少被骗（0 到 0.67）。

第三，良性结论的非对称证据以一定代价弥补了这一缺口。加上该规则后，\emph{spoof} 下的攻击成功率在五个模型上都降到 0。控制器会多运行一个探针，发现它与扫描相矛盾，最后给出 \textit{other}，因此这些案例全部升级。该规则也让 \emph{inject} 下的攻击成功率保持为 0。其代价落在真正的良性案例上：两个良性原因上的完成率从 1.00 降到 0.50，平均成本从 1 个单位升到 5 或 6 个，因为在这个环境中监控误报只有一个特异特征，无法得到佐证。

第四，v1.1 研究把这些效应归因到各个组件（\cref{tab:v11attack}；另加三种注入文本和伪造的上游数据源，五个模型全部参与）。阻止注入式结案的是结束守卫：在每个模型上，所有带守卫的配置都没有把 72 个需处置案例中的任何一个结为良性；而有控制器选择和停止但没有守卫时，规划器在 72 个中的 36 到 48 个回合里抢先以注入的结论结束。从提示中去掉原始响应文本也能阻止所有注入式结案，即使没有控制器；对 Qwen2.5-32B 和 72B 这没有任何代价，但 Qwen2.5-7B 此时只能解决 72 个中的 7 个，因此对弱模型而言，仅靠解析隔离是以可用性为代价换取完整性。控制器停止把守卫留下的未解决回合从 44--66 个降到 72 个中的 2--42 个。\texttt{source\_ips} 和 \texttt{threat\_intel} 共同读取的伪造上游数据源，与单条伪造探针一样击败了控制器（每个模型都是 18 个中的 18 个），还误导了较大的 LLM 本身（Memory-only 下最多 18 个中 15 个）。两种佐证规则都把这些案例全部升级，但按探针计数的规则之所以成立，只是因为控制器的第二个探针恰好读取了另一个来源；如果它运行的是 \texttt{threat\_intel}，两个探针就会被算作两次确认，而按来源组计数从机制上防止了这一点。两种规则都使真正良性案例的完成率减半（6 个中 3 个）。所有计数都来自同一个环境，一个 0/18 的格子只能给出很宽松的上界（约 15\%，单侧 95\%，即使其六个原因和三次重复相互独立）。

\subsection{公开安全数据与本评测的适配性}
\label{sec:realdata}
受控环境自然会引出一个问题：这些结果在真实数据上是否成立？我们考察了最接近的三个公开数据集能否检验本文所定义的调查策略；这需要告警让多种解释同时成立、探针的成本和信息量各不相同，以及客观的真值。附录~\ref{app:public} 给出了版本、文件和方法；ExCyTIn 的可行性检查读取了其测试题（勘误 E-10），而 GUIDE 的测试集从未读取。在我们考察的版本和子集中，没有一个适配。ExCyTIn-Bench~\citep{excytin} 的题目通常直接点名要定位的告警（418 道训练题中的 54.8\%），标准的指标关联探针找到答案的频率并不高于干扰项。在 GUIDE~\citep{guide} 中，仅组织身份就携带了分级 1.50 比特中的 1.03 比特，而且在冷启动事件上证据整合对真阳性的排序并不优于历史查表（AUROC 0.755 对 0.759）。在我们审查的 27 份 OTRF~\citep{otrf} 远程执行录制中，一条只看告警文本的规则就能区分 46 条告警中的 44 条。三者缺少的东西相同：看起来像日常管理的攻击，与看起来像攻击的合法管理配对，并有客观标注。这并不意味着它们的遥测无法变成交互式评测：Cyber Defense Benchmark~\citep{cyberdefensebench} 把 OTRF 录制包装成了 SQL 威胁狩猎环境，只是其真值来自 Sigma 规则、也没有触发告警，因此测量的是威胁狩猎而不是告警分诊。
