\paragraph{普遍程度} 在报告成绩所用的版本上，\oN{} 道测试题中有 \oNamed\% 对终点告警的描述足够具体，仅凭词重叠就能把它排在该事件全部告警的第一位（95\% 区间 \oNamedLo--\oNamedHi）；\oAdj\% 的答案是这条告警的实体（\cref{tab:excytin}）。贯穿示例很典型：题目描述了生成它的那条告警，因为生成的题目必须没有歧义，而这段描述足以找到它。在最新版本上比例相同：我们在其测试集上只运行一次冻结规则，得到 \exNamed\%（区间 \exNamedLo--\exNamedHi），训练集为 \exTrainNamed\%。

\paragraph{不调查也能精确答对} 从排名第一的告警中取第一个所问类型的实体，可以精确答对 \oGraph\% 的题目（区间 \oGraphLo--\oGraphHi）。同一规则只用任何智能体都能查询的 \texttt{SecurityAlert} 表，答对 \oTable\%（区间 \oTableLo--\oTableHi）。两条规则都不读告警表以外的日志表，不做跳转，也不用 LLM。规则很粗糙：一条告警有多个同类实体时只取第一个，题目问的类型不在关键词表中时就失败。它们是查找所能达到的下限，而不是上限。

\paragraph{与报告成绩比较} \Cref{fig:floor} 把两种查找与基准作者报告的 \oModels{} 个模型放在一起。图查找超过其中 \oBelowGraph{} 个模型的平均奖励，包括 GPT-4o（\exGptFo）；告警表查找超过 \oBelowTable{} 个。这一比较对模型有利：报告的奖励来自 LLM 判分，还包含中间步骤的部分分，而查找只有最终答案精确匹配才得分。因此低于下限的模型并不是被测出"调查能力弱"；在这个基准上，它们的分数根本不能说明它们在调查。

\paragraph{分事件成绩} 各事件中点名终点告警的题目比例不同（\cref{app:excytin}）。在八个事件上，\oModels{} 个模型中有 \oHPos{} 个在点名题较多的事件上得分更高（Spearman $\rho$ 中位数 \oHMedian）。只有八个事件时，这种相关可能来自事件间的任何差异；\cref{sec:scores} 在单题层面检验它，结果不成立。

\subsection{SIABench：攻击有一个地址}
\label{sec:siabench}

SIABench 分诊集中全部 \siaTP{} 条真阳性告警都涉及 172.16.0.1，而 \siaMajority{} 条误报都不涉及，所以规则"当且仅当出现 172.16.0.1 时判为真阳性"在 \siaN{} 条中答对 \siaRule{} 条。这个地址是 CIC-IDS2017 中攻击网络进入受害网络的网关~\citep{cicids2017}，是数据集生成方式的性质，而不是攻击本身的性质。基准把告警放在场景文字中交给模型，所以线索就在提示词里。全部回答"误报"已经得到 \siaMajorityPct\%。报告的准确率从 \siaMini\%（GPT-4o-mini）到 \siaGptFive\%（GPT-5），DeepSeek-Reasoner 为 \siaDeepSeek\%~\citep{siabench}。没有逐题日志，我们无法判断哪些模型用了这个地址；要点在于，具有这种结构的 35 条告警无法区分分析抓包的模型和不分析的模型。

\subsection{GUIDE：定级跟着组织走}
\label{sec:guide}

GUIDE 训练集的 \gIncidents{} 个事件来自 \gOrgs{} 个组织，仅组织身份就携带了定级 \gH{} 比特熵中的 \gMIorg{} 比特；若干大组织给所有事件同一个定级。沿用同一组织此前对同一检测器的定级，在之后的事件上正确率为 \gHistPct\%（组织内按时间切分，\gDev{} 个事件，其中 \gSeen\% 有这类历史），真阳性召回 \gHistTP。只用事件自身告警和证据元数据、在其他组织上训练的分类器，准确率为 \gHeldMin--\gHeldMax，低于多数类（\gHeldMajority）。标签记录的至少同样是组织的分诊政策，而不只是事件本身；在 GUIDE 上评测时，如果模型能获得组织身份或历史，就可以靠回忆政策得到高分。

\subsection{OTRF：攻击带着名字，良性事件都是例行操作}
\label{sec:otrf}

在 \otRec{} 个远程执行技术的录制中，我们找到 \otN{} 条不同的服务和计划任务告警：\otAttack{} 条来自模拟攻击，\otBenign{} 条来自操作系统。只看告警文字的规则答对 \otN{} 条中的 \otRuleCorrect{} 条。八条攻击告警中有六条由工具命名（\texttt{MordorSchtask}、20 位随机字母的服务名等），而良性告警是 Windows 更新、组策略任务和每用户服务，从来没有管理员使用同样的工具。两个例外属于同一个场景：一个名为 \texttt{EventCacheManager}、放在 Windows \texttt{SoftwareProtectionPlatform} 任务目录中的任务。一个探针就能把它区分出来：与录制中所有系统任务不同，它是由域用户经网络登录创建的（\cref{app:otrf}）。用这类录制构建的分诊任务，测的是模型能否认出攻击工具的名字。

\subsection{我们自己的环境：一段脚本就能解出}
\label{sec:own}

手工构建的基准有第四类捷径。在我们此前为 LLM 分诊智能体研究构建的两个模拟分诊环境中，一个不含 LLM 的控制器（按期望信息增益选探针，一条观测确认领先原因即停止）在 sec-triage 的 \envSecN{} 个案例中验证了 \envSec{} 个正确原因，在 sigma-triage 的 \envSigmaN{} 个中验证了 \envSigma{} 个。脚本已经满分，这两个环境无法表明模型的调查比固定程序更好；我们放入循环的五个开放权重 LLM（7B 到 72B 参数）也没有一个做得更好。环境规定了每个原因产生哪些观测；一旦这个模型被写下来，分诊就是在其中查表。补救方法，即配对设计，在 \cref{sec:design} 讨论。

\smallskip\noindent\textbf{发现 1（RQ1、RQ2）。}每个被审计的基准都存在不调查的规则，且每条规则都达到或超过报告成绩的相当部分：在 ExCyTIn 上，不含 LLM 的查找超过 \oModels{} 个智能体中的 \oBelowGraph{} 个；在 SIABench 上，一条地址检查全部答对。
