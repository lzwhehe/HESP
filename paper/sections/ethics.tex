\section*{Ethics Considerations}
This work involves no human subjects and no live systems. All triage episodes run against loopback sandboxes we built; the agent issues only read-only queries and never sends attack traffic. The adversarial variants simulate an attacker inside those sandboxes: no attack was executed against any system, and no exploit or attack tooling was written or run. The public datasets are used within their licences: ExCyTIn-Bench (code MIT, data CDLA-Permissive-2.0, released for research), GUIDE (anonymized incidents released by Microsoft), OTRF Security-Datasets (MIT), and SigmaHQ detection rules (Detection Rule License 1.1, with attribution). We read only the training material of ExCyTIn-Bench and GUIDE, never their test splits, and we do not redistribute per-incident GUIDE data. The OTRF recordings contain emulated attacks in a lab domain and no personal data.

\paragraph{Potential harms of publication} \hesp{} is a defensive tool. The adversarial results describe how an attacker could mislead an automated triage agent, namely by writing instructions into log fields or by making one source report a benign-looking answer. Both techniques are already known in general form, and we publish them together with the measured mitigations: deciding verdicts from structured evidence neutralizes the first, and requiring independent corroboration for benign verdicts neutralizes the single-source version of the second. We consider it more harmful to deploy triage agents without knowing these failure modes than to report them. We release the controller, environments, and journals, but no attack tooling.
