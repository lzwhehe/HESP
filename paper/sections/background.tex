\section{Background}
\label{sec:background}

\paragraph{LLM agents in security operations} A security operations center (SOC) receives alerts from detectors and must decide, for each one, whether it reflects an attack and what the attack touched. Vendors and researchers now place LLM agents in this loop: the agent receives an alert, queries logs or packet captures through tools, and returns a verdict or an indicator such as the attacker's IP address~\citep{guide,cortex,sentinelrl}. Investigation is the expensive part of the analyst's job, and it is what these agents are meant to take over: following an alert to related evidence, combining several weak signals, and ruling out benign explanations that look the same at first glance.

\paragraph{Benchmarks} We audit four public benchmarks or datasets used to evaluate such agents, chosen because they are recent, publicly available, and claim to measure investigation rather than recall (\cref{tab:benchsetup}).
\emph{ExCyTIn-Bench}~\citep{excytin} builds an alert--entity graph for each of eight simulated multi-stage incidents in an Azure tenant and generates questions from paths on it: the start alert and its entities are the context, and the answer is an entity of the end alert. An agent answers by issuing SQL queries over roughly 45 log tables; a GPT-4o judge scores the answer and gives partial credit for intermediate steps.
\emph{SIABench}~\citep{siabench} gives an agent a Snort alert and the packet capture behind it and asks whether the alert is a true or false positive; its 35 alerts come from the CIC-IDS2017 dataset~\citep{cicids2017}.
\emph{GUIDE}~\citep{guide} contains 1.6 million real alerts from Microsoft Defender XDR, grouped into incidents from 6.1 thousand organizations and graded by those organizations' analysts as true, benign, or false positive.
\emph{OTRF Security-Datasets}~\citep{otrf} contains host telemetry recorded while ATT\&CK techniques were executed in a lab domain; it is widely used to build detection and triage tasks.

\paragraph{Running example} \Cref{fig:example} shows an ExCyTIn training question. The context describes an alert about an anomalous scheduled task on a host. The question asks for the IP address recorded in a related alert, and it names that alert: ``Anomaly detected in ASEP registry''. The benchmark generated the question from the path start alert $\rightarrow$ host $\rightarrow$ end alert, and expects an agent to pivot from the scheduled-task alert to the host and from the host to the related alert. An agent does not need the pivot. One query for the named alert in the \texttt{SecurityAlert} table returns its entity list, which contains exactly one IP address, the answer. We call such a path from the question to the answer that skips the investigation the benchmark intends a \emph{shortcut}.

\paragraph{Why shortcuts matter here} Shortcut learning is well documented in machine learning: models exploit cues that happen to predict the label in a benchmark but not in deployment~\citep{geirhos2020shortcut}, and annotation artifacts let a classifier solve a task from the hypothesis alone~\citep{gururangan2018artifacts}. Security has its own versions: spurious correlations and sampling bias inflate results of learning-based detectors~\citep{arp2022dos}, and labeling and generation artifacts in CIC-IDS2017 are known~\citep{engelen2021cicids}. For LLM agents in a SOC the consequence is direct. A benchmark score is the evidence a defender uses to decide whether an agent can be trusted to close alerts. If the score is earned by looking up a named alert, it says little about the cases that matter, where nothing names the answer and an attacker has made the malicious activity look routine.
