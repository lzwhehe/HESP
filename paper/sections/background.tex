\section{Background}
\label{sec:background}

\paragraph{Alert triage} Alert triage decides, for each alert that detection raises, what actually happened and whether a response is needed~\citep{nodoze}. It differs from attack investigation, which reconstructs a complete attack story from a point of interest~\citep{kairos,clouseau}, in that it ends with a single verdict, i.e., the cause of the alert together with the evidence that supports it. The analyst reaches the verdict by querying the environment, and queries differ in cost and in how well they separate the candidate explanations: some are cheap and decisive for one explanation, whereas others, such as a threat-intelligence lookup, are slow and return the same answer for several attacks. Consider an alert that reports a spike in authentication failures and HTTP errors on a web tier. It looks like credential stuffing, but the same symptom can come from SQL-injection probing, an authorized vulnerability scan, a misclassified health check, or an administration panel exposed to the public network; reading the admin panel's configuration, one cheap query, settles the last explanation at once, but only an investigator who keeps that explanation in view will run it. The order of queries therefore decides how quickly an investigation ends, and the investigator must also judge when the evidence suffices.

\paragraph{Local LLM agents} An LLM agent couples a language model with tools: at each step, the model reads the task and the observations so far, and then calls a tool or ends the task~\citep{react}. Open-weight models such as Qwen2.5 and Llama~3.1 run on an organization's own hardware, with 4-bit weights up to 72B parameters on one GPU, which keeps telemetry on the premises but rests every step of the loop on a weaker model.

\paragraph{Injection into agent inputs} An agent that reads retrieved content can be steered by instructions hidden in it, namely, indirect prompt injection~\citep{greshake2023}, which AgentDojo~\citep{agentdojo} benchmarks on tool-using agents. Log injection, in which unescaped user-controlled fields forge or corrupt log records, is an older instance of the same problem~\citep{owasp_loginjection}. In triage both apply, because request payloads, user agents, command lines, and ticket text are written by whoever caused the alert and are copied into the logs the agent reads.
