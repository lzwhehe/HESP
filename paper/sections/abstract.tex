\begin{abstract}
Security teams increasingly want LLM agents for alert triage, yet many cannot send telemetry to a hosted model and must run small local models instead. We find that small local models often fail at triage for reasons unrelated to security knowledge. They repeat the same query, stop before collecting decisive evidence, or never commit to a verdict at all. We present \hesp{} (Hypotheses $\rightarrow$ Evidence $\rightarrow$ State $\rightarrow$ Planning), a controller that sits between the model and its read-only investigation tools. \hesp{} keeps an explicit ledger of competing explanations. It chooses the next probe by expected information gain per unit cost, accepts a verdict only when current-state evidence supports it, and journals every prediction before the observation it predicts.

We evaluate \hesp{} in a controlled alert-triage environment. The environment has eight hidden causes, including real attacks, misconfiguration, authorized activity, and false positives, plus base, noisy, and drifting variants. Every study was pre-registered and frozen before it ran. The evaluation covers five open-weight models from two families, 7B to 72B, and more than 7{,}000 audited episodes. With prediction tables estimated only from LLM-free development episodes, \hesp{} raises verified triage completion of Qwen2.5-7B from 0.125 to 1.000 ($+0.875$, 95\% CI $[+0.74,+0.97]$). Completion matches that obtained with oracle tables, at slightly higher probe cost. Gains for larger models are smaller (32B: $+0.25$; 72B: $+0.11$, interval touching zero). A clean randomized control, in which the planner receives identical information whatever the selector, attributes $+0.26$ to $+0.35$ of completion to the information-gain ranking itself on every model that concludes. Handing probe choice to the controller helps the 7B model but hurts 32B and 72B models, whose own choices beat random ones.

A second-family replication exposes the method's boundary. Llama-3.1-8B never concludes in any configuration: \hesp{} decides what to probe but not when to stop. A follow-up study lets the controller also decide when to stop, using the same evidence rule. This lifts Llama-3.1-8B from 0 to 0.917 ($+0.917$, 97.5\% CI $[+0.79,+1.00]$). Once stopping is supplied, however, controller probe selection no longer beats the model's own choices on this model ($+0.056$ $[-0.07,+0.18]$): what it lacked was a stopping rule, not a probing strategy. Qwen2.5-7B lacked both. Finally, we measure three public security datasets (ExCyTIn-Bench, GUIDE, and OTRF Security-Datasets) and show why none of them can test investigation policies. The answer is named by the alert, set by organizational labeling policy, or given away by tool artifacts. We release the code, frozen protocols, errata, and the episode journals of every study from v0.6 on.
\end{abstract}
