\section{Discussions}
\label{sec:discussion}

\paragraph{Recommendations for deployment} As observed in our study, an attacker reaches a local triage agent's verdict through whatever the model decides and whatever it reads. We therefore recommend \hesp{} with EIG/cost selection, the finish guard, the confirmation stop, source-group corroboration for benign verdicts, and the recovery rule after rejected finishes, and, wherever the model reads raw logs, a rule parser first with the reader-trust rule on top; every verdict should reach an analyst together with its cited evidence and journal, so that a residual attack is a delayed response rather than an unattended closure. This configuration sits at the safe end of the frontier in \cref{tab:v12policy}: where causes share tools and no single observation separates them, it escalates most cases rather than risk closing an attack as the legitimate activity it resembles. A deployment that values automation more can accept joint evidence, and should expect such mistakes.

\paragraph{What each rule cannot stop} Each rule closes one path and assumes something about the attacker. The finish guard contains text because text never enters the ledger; it does nothing against forged evidence. Source-group corroboration contains a forged source as long as the attacker forges one group; an attacker who controls two independent groups defeats it, and which sources are independent is a property of the deployment, not of \hesp{}. The reader-trust rule contains forged readings as long as a trusted parser exists and cannot itself be fooled; ours is immune to the tested attacks by construction, and a rule parser that could be misled would move that trust. What remains in every case is a cost rather than a closure: rejected dismissals, forged sources, and untrusted readings all end in escalations that consume analyst time.

\paragraph{Where the model is still needed} With structured observations, the controller accounts for all of the measured gain: the earlier advantage of strong models that decided when to stop came from waiting for a confirming signature, which a rule in the controller reproduces without an LLM. The model is needed for reading, because it reads a changed log format that a rule parser cannot. That role is also where the model is dangerous, and the reader-trust rule lets a deployment keep the reading without the closure: an attack can still be confirmed from the model's readings, while every benign case is escalated until a trusted reading exists. The parser, not the planner, is therefore the component to harden.

\paragraph{Prediction tables from resolved tickets} The prediction tables are the main deployment cost. Ours ran every probe on cases of known cause; resolved tickets record only the probes an analyst chose, so tables estimated from them face selection bias and missing counterfactual outcomes. The confirmation rule adds one more requirement, namely that at least one probe single out each cause; when the tables blur two causes, it escalates every case, so it keeps errors low by giving up automation, and the ten-fold specificity threshold sets that trade-off (\S\ref{sec:policy}).

\paragraph{Public security data}\label{sec:realdata} To see whether these results could be tested on real data, we asked whether the three public datasets that come closest could test an investigation policy as defined here, which needs alerts that leave several explanations plausible, probes that differ in cost and informativeness, and objective ground truth (Appendix~\ref{app:public}; the ExCyTIn feasibility checks read its test questions, erratum E-10, whereas GUIDE's test split was never read). In the subsets we examined and with our adaptations, we found no setting that fits this question: most ExCyTIn-Bench~\citep{excytin} training questions name the alert to locate (54.8\%); in GUIDE~\citep{guide}, organization identity carries 1.03 of the grade's 1.50 bits and evidence integration does not rank cold-start true positives better than history lookup (AUROC 0.755 against 0.759); in the 27 OTRF~\citep{otrf} remote-execution recordings we audited, a rule on the alert text separates 44 of 46 alerts. Paired attacks and legitimate administration that use the same tools, under objective labels, are what these subsets lack; the Cyber Defense Benchmark~\citep{cyberdefensebench} shows that such telemetry can be made interactive.
