# 立项书：提升 7B/8B 模型在安全日志调查中的可用性（2026-10-01，按 security-idea-generation skill）

## 1. 盘点

**已有的可靠发现**
1. ExCyTIn 逐题日志：前沿模型的失败主要不是"调查不够深"，而是取回、报告不可靠（最强模型在一次查询即可答对的题上错 31%）。
2. DiagChain（arXiv:2608.03591）报告：小模型更常"忘记已经看到的证据"，大模型的瓶颈是证据排序。他们测过 Qwen2.5-7B。
3. AuditBench（arXiv:2606.10281）报告：小模型在多个任务上不输大模型，日志表示方式（raw 对比 edge）影响很大。
4. 我们自己的 HESP 实验：控制器把 7B 从低完成率拉到接近满分，但不含 LLM 的控制器单独也能做到（审稿致命点）。另外，伪造的变更工单类记录会被模型采纳。
5. 审计工作给出 ExCyTIn 的不调查下限（31.9%）和 186 道抗捷径题。

**资产**：ExCyTIn 全部数据 + 14 次前沿运行逐题答案；AuditBench、DiagChain 公开仓库；H100（Qwen-7B、Llama-8B、phi-4 常驻）；可租 RTX PRO 6000 跑 72B；HESP 控制器与审计脚本；预注册流程。

**约束**：不付费 API；不读测试集调参；AuditBench 仓库没有 LICENSE 文件，只做评测、不再分发，必要时联系作者。

## 2. 候选卡片

### A. 证据放在模型外面，7B 就够用（A9 根因 + 简单方法）
- 一句话：小模型做安全日志调查失败，主因是拿不住证据，而不是不会推理；把证据账本、类型化工具和答案核验放到模型外面，7B 在三个公开基准上达到 GPT-4o 级别。
- 最近工作：DiagChain 诊断了"小模型丢证据"但没有修；AuditBench 发现表示方式重要但只测 API 模型。差异：我们修复它，并在三个外部基准上验证。
- 必须守住：报告不含 LLM 的下限（吸取 HESP 教训），在抗捷径题上也要有提升，否则就是"脚本在干活"。
- 评分：后果 4、意外 4、普适 4、沙箱外证据 5、可操作 5、新颖 3（待检索）、可行 4、风险 3。

### B. 变得好用，会不会也变得好骗？（A2 防御变武器 + A5 自适应攻击）
- 一句话：让小模型读更多日志、调更多工具，同时扩大了攻击者可写字段（user-agent、文件名、命令行、工单）的影响；衡量能力提升带来的被误导风险，并给出不增加风险的设计。
- 来源：HESP 读取器信任实验（伪造工单被采纳）、LogInject。
- 单独成文偏小，**作为 A 的安全性 RQ 最合适**：安全顶会要求能力论文也有威胁模型和自适应攻击。

### C. 本地小模型 SOC 就绪度测量（A4/A3）
- 三个基准上系统测 7–8B 开源模型对比前沿模型与不调查下限。公司吸引力弱，作为 A 的附带结果即可。

### D. 训练一个安全调查专用 7B（蒸馏 / 强化学习）
- 公司吸引力最高，但顶会安全审稿会看作"把已知训练方法用到新领域"（红旗）。算力和时间成本高，且容易污染测试集。
- **作为 A 的可选第二阶段**：在 A 的结构之上再训练，测训练还能多带来多少。

## 3. 选择

**A 为主线，B 作为安全性 RQ，D 作为可选阶段。**

暂定题目：*Small, Local, and Hard to Fool: Making 7B Models Usable for Security Log Investigation*

暂定主张：把证据账本、类型化工具和答案核验放在模型之外，单卡运行的 7B/8B 模型在 ExCyTIn、AuditBench、DiagChain 上达到 GPT-4o 级智能体的水平；同时，面对攻击者可写日志字段中的注入，它不比基线更容易被误导。

**研究问题**
- RQ1 小模型为什么失败？在三个基准上对 7B 的失败做分类（格式、SQL/查询、丢证据、选错实体、过早结束）。
- RQ2 外置结构能把 7B 提升多少？与原始提示、最佳提示、ReAct、不含 LLM 的下限、前沿模型报告值比较；包括抗捷径题。
- RQ3 每个组件各贡献多少？消融：工具层 / 证据账本 / 答案核验 / （可选）蒸馏。
- RQ4 变好用之后是否变好骗？在攻击者可写字段中注入指令或伪造证据，比较基线与改进版的判定翻转率。
- RQ5 成本：单卡延迟、token、每题成本；"自动处理比例 vs 准确率"曲线。

**证据计划**
- ExCyTIn：o1 测试集 589 题；用同一评分器重新计分 14 次前沿运行的公开答案，做公平对比。
- AuditBench：lab 与 OpTC 场景、四个任务，对比论文中的 GPT-5、Gemini、Llama 4 Maverick。
- DiagChain：论文已测 Qwen2.5-7B，可直接作为同模型基线。
- 模型：Qwen2.5-7B、Llama-3.1-8B（必要时加 Qwen3-8B 或安全领域 8B 模型，名称待核实）。

## 4. 证伪实验（1–2 天，H100）

Qwen2.5-7B，ExCyTIn 训练集抽 50 题，原始提示对比"工具层 + 证据账本 + 答案核验"，本地评分。
- 通过条件：提升 ≥ 15 个百分点，且在样本中的抗捷径题上高于查表下限（0）。
- 不通过：回到 D（训练）或改选 B 为主线。
- 顺带检查：AuditBench 的场景文件名含 `attack`/`benign` 字样，确认推理时是否会传给模型（可能又是一处 S1 型泄漏）。

## 5. 风险
- 新颖性：需检索"小模型 + 安全调查智能体"的近期工作（安全领域专用小模型、日志分析小模型等）。
- 可比性：我们不用 GPT-4o 判分，必须用同一本地评分器重算所有对比方。
- "脚本在干活"：每张主表都带不含 LLM 的下限和抗捷径子集。
- 数据许可：AuditBench 无 LICENSE，只评测不分发。

3. 第 4 周：RQ4 攻击实验。
4. 第 5–6 周（可选）：72B 生成训练题轨迹，LoRA 蒸馏 7B。
