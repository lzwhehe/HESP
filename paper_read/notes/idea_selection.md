# 选题记录（2026-10-01，按 security-idea-generation skill）

## 1. 盘点

**可靠的观察（不是按构造成立的）**
1. 我们自己的环境里，不含 LLM 的控制器就能解决两个确定性任务族的全部案例，72B 模型和为基线调好的提示都没有带来增益。
2. 公开数据：ExCyTIn-Bench 有 54.8% 的题目在文字里点名要找的告警；GUIDE 的等级标签 1.50 比特中有 1.03 比特来自组织身份；OTRF 中一条基于告警文本的规则能区分 46 个告警中的 44 个。
3. 模型是否采纳攻击者的读数，取决于有没有真实记录与之冲突（漂移格式 84/84 采纳，文档格式下 `source_ips` 0/42）。
4. 我们加的每条安全规则，都把"误关"变成了"升级"（注入下 44–72/72 悬而未决；漂移攻击下读取器信任让每个回合都升级）。
5. 小模型不会停（Llama-3.1-8B 3,389 次决策从不结束），且不同模型的失败位置不同。

**资产**：ExCyTIn（本地 4.9 GB，含图和题目）、GUIDE 训练集、OTRF、Sigma 仓库（含回归测试用的 EVTX 样本）、我们的控制器与三个环境、H100（Qwen-7B、Llama-8B、phi-4）、预注册与审计流程。

**约束**：不付费 API；GUIDE 测试集不读；只在本地或公开数据上实验。

## 2. 候选 idea 卡片

### C1：安全运营 LLM 基准在测"查找"而不是"调查"（A3 重新评估 + A10/A8）
- 一句话：面向 SOC 的 LLM 智能体基准存在系统性捷径，不做调查的简单基线就能达到前沿模型报告的成绩；去掉捷径后成绩和排名会变。
- 来源：观察 1、2。
- 最近工作：SIR-Bench（2604.12040）指出要区分"真正调查"和"照抄告警"，但它是新建一个基准，没有审计现有基准；DiagChain、CyberClear、AuditBench 是新基准；"Sometimes Simpler is Better"（USENIX'25）对溯源 IDS 做了同类重新评估，但不涉及 LLM 智能体基准。
- 证伪实验（ExCyTIn 训练集 418 题，不含 LLM，不读日志）：
  - 只用题目文字与告警名的词重叠，62.9% 的题目把终点告警排在第一；
  - 78.9% 的题目，答案是终点告警的直接相邻实体；
  - 按类型取排名第一告警的相邻实体，选第一个，命中 30.4%（GPT-4o 在测试集上的平均奖励为 0.293，含部分得分）。
  - 对照：只在全部日志里做关键词查找的朴素基线只有 9.1%，所以捷径来自"题目点名终点告警"，而不是"日志里随便搜一下"。
  - **结论：卡片通过证伪实验。**
- 评分：后果 4、意外性 4、普适性 4（需覆盖多个基准）、实验在自己沙箱之外 5、可操作性 5（修正协议和捷径检验工具）、新颖性 4、可行性 4、风险 3。

### C2：加固之后，攻击者转向"耗尽分析员"（A2 防御变武器）
- 一句话：一旦 LLM 分诊被加固，"失败时交给人工"就成了攻击面：攻击者用很低的成本制造大量升级，淹没真正的攻击。
- 来源：观察 4。
- 最近工作：未检索到直接相关工作；"Your Shield is My Sword"等同类型论文证明这一类型受认可。
- 问题：目前证据全在我们自己的环境里；分析员成本模型的真实性难以证明。
- 评分：后果 4、意外性 4、普适性 3、实验在沙箱之外 2、可操作性 3、新颖性 4、可行性 3、风险 2。**实验在沙箱之外一项低于 3，按 skill 规则淘汰。**

### C3：LLM 读日志时何时会被说服（A9 根因）
- 来源：观察 3。最近工作 LogInject 已测了被动注入，差异只在"冲突决定采纳"这一机制。
- 评分：新颖性 3、普适性 3、可行性 4。作为 C1 的一节价值不大，作为独立论文偏小。**保留为后续工作。**

### C4：HESP 控制器本身（A6 设计防御）
- 安全结果大多按构造成立，模型角色尴尬。评分：意外性 2、实验在沙箱之外 2。**淘汰为主线**；它在 C1 中的位置是"在可控环境里，不做调查的简单程序就能拿满分"的一组证据。

## 3. 选择

**选 C1。** 理由：唯一一个通过证伪实验、并且证据不依赖我们自己写的环境的方向；属于安全顶会认可的"重新评估"类型（同届 USENIX 有多篇）；对整个领域有用，产出是可以复用的捷径检验方法和修正后的评测协议；绝大部分实验可以用 CPU 完成。

**暂定题目**：Lookup, Not Investigation: Shortcuts in Benchmarks for LLM Security-Operations Agents

**暂定主张**：在我们审计的 SOC/调查类 LLM 基准中，相当比例的题目不需要调查就能回答：题目点名了答案所在的告警，标签由组织身份等外部线索决定，或者告警文本本身就区分了类别。不做调查的基线能达到前沿模型报告的成绩；按"去捷径"重新划分题目后，模型成绩会下降、排名会变化。

**研究问题（草案）**
- RQ1 捷径有多普遍？在每个基准上测四类捷径：题目泄漏终点、标签由标识符决定、单步查找即可回答、告警文本即可分类。
- RQ2 不调查的基线能拿多少分？与论文报告的模型成绩比较。
- RQ3 去掉捷径后发生什么？在"无捷径子集"上用本地模型（Qwen-7B、Llama-8B、phi-4）复测，看成绩和排名的变化。
- RQ4 怎样构建不能靠捷径作答的题目？给出检验清单，并用配对的"攻击/相似合法活动"题目（我们的 comp-triage 思路、Sigma 回归样本）做正面示例。

**下一步**：确认其他基准（SIABench、AuditBench、CyberClear、DiagChain、SIR-Bench、Cyber Defense Benchmark）的数据是否公开可得，然后写预注册协议：在 ExCyTIn 测试集上冻结捷径基线的规则后只运行一次。
